# Reinstate Content Brief

## Inputs

Gather from the task or repository:

- target audience
- real user problem
- primary query
- search intent
- current product capability
- relevant release or version
- evidence
- desired next action

Use `reinstate-product-truth` first.

## Workflow

1. Confirm the page has one dominant intent.
2. Search existing content for overlap.
3. decide whether to update an existing page instead.
4. define:
   - H1
   - direct answer
   - primary query
   - secondary questions
   - outline
   - internal links
   - evidence
   - media
   - schema candidates
5. list limitations.
6. list every claim requiring verification.
7. define acceptance criteria.
8. propose frontmatter.

## Required output

```markdown
# Content brief

## Page
- title
- URL
- type
- owner
- status

## Audience and intent
- audience
- problem
- primary query
- secondary questions
- intent
- next action

## Product truth
- capabilities
- limitations
- evidence
- version

## Outline
- H1
- direct answer
- H2 and H3 structure

## Links
- inbound opportunities
- outbound internal links
- external sources

## Structured data
- primary type
- breadcrumb
- optional types

## Media
- diagrams
- screenshots
- data

## Acceptance criteria
```

## Quality bar

The planned page must contain original value such as tested commands, implementation details, a diagram, a benchmark, compatibility evidence, or maintainer insight.
