## R1 — OpenCode `storage/message/<session-id>/` schema + Windows root

**Status: answered** (Windows root + file message schema).  
**Escalation for WP-09:** newest OpenCode also persists messages in SQLite
(`SessionMessageTable` in `packages/core`). The file layout below is the
confirmed `Storage` key layout and MessageV2 JSON shape used by
`storage/message/…`. If a device has only the SQL store and no
`storage/message/` tree, the file reader must fail closed / report
`omitted` for capsule body — do not invent a SQL schema here.

### Windows root

| Claim | Confidence | Evidence |
| ----- | ---------- | -------- |
| `%USERPROFILE%\.local\share\opencode` | **Documented** + source | Vendor troubleshooting (`opencode.ai/docs/troubleshooting/`): Win+R paste `%USERPROFILE%\.local\share\opencode`. Source `packages/core/src/global.ts`: `Path.data = path.join(xdgData, "opencode")`. `xdg-basedir` uses `XDG_DATA_HOME \|\| homedir/.local/share` on **all** OSes — **not** `%LOCALAPPDATA%`. |

Override: `XDG_DATA_HOME` when set.

### Message record layout

```
<data>/storage/message/<sessionID>/<messageID>.json
<data>/storage/part/<messageID>/<partID>.json
<data>/storage/session/<projectID>/<sessionID>.json
```

`Storage.write(key)` → `path.join(dir, ...key) + ".json"` with
`dir = Global.Path.data/storage` (`packages/opencode/src/storage/storage.ts`).

### Message JSON schema (MessageV2.Info)

From `packages/opencode/src/session/message-v2.ts` (discriminated on `role`):

**User**

- `id` (`msg…`), `sessionID` (`ses…`), `role: "user"`
- `time.created` (number ms)
- `agent` (string), `model: { providerID, modelID }`
- optional: `format`, `summary`, `system`, `tools`, `variant`

**Assistant**

- `id`, `sessionID`, `role: "assistant"`
- `time: { created, completed? }`, `parentID`
- `modelID`, `providerID`, `mode`, `agent`
- `path: { cwd, root }`, `cost`, `tokens: { input, output, reasoning, cache: { read, write } }`
- optional: `error`, `summary`, `structured`, `variant`, `finish`

**Body text** is not inlined in the message file; it lives in **parts**
(`type: "text"`, etc.) under `storage/part/<messageID>/`.

## R2 — Grok Build session filename, JSON schema, workspace key

**Status: answered**

There is **no** single `session-<timestamp>.json` file. Each session is a
**directory**:

```
$GROK_HOME/sessions/<encoded-cwd>/<session-uuid>/
  summary.json
  updates.jsonl          # authoritative restore log
  chat_history.jsonl     # model-facing ConversationItem stream (v1)
  plan.json
  rewind_points.jsonl
  signals.json
  feedback.jsonl
  compaction_checkpoints/
  compaction_requests/   # full pre-compact request payloads
  subagents/
```

Evidence: xAI user guide
`crates/codegen/xai-grok-pager/docs/user-guide/17-sessions.md` and
`xai-grok-shell` storage constants (`SUMMARY_FILE`, `UPDATES_FILE`,
`CHAT_HISTORY_FILE`).

### Workspace key encoding

From `xai-grok-config/src/paths.rs` `encode_cwd_dirname`:

1. URL-encode the absolute cwd.
2. If encoded length ≤ 255 bytes → that string is the directory name.
3. If longer → `{slug}-{blake3_hex16}` (slug from path leaf, ≤40 chars) and
   write original cwd bytes to a `.cwd` file inside the directory.
4. Decode: URL-decode if result looks absolute; else read `.cwd`.

Examples in fixtures:

- macOS: `%2FUsers%2Ffixture-user%2Fcode%2Fdemo`
- Windows: `C%3A%5CUsers%5Cfixture-user%5Ccode%5Cdemo`

### `summary.json` (index entry)

`Summary` wraps `Info { id, cwd }` plus counts/timestamps/model
(`xai-grok-shared/src/session/info.rs`, `persistence.rs`).

### `chat_history.jsonl` (format version 1)

Tagged `ConversationItem` enum (`type` snake_case): `system`, `user`,
`assistant`, `tool_result`, `backend_tool_call`, `reasoning`
(`xai-grok-sampling-types/src/conversation.rs`).

## R3 — Grok `/compact` and Gemini `$rewindTo`: destroy or preserve?

**Status: answered**

### Gemini `$rewindTo` — preserve on disk, destroy in active view

| Layer | Behavior |
| ----- | -------- |
| On-disk JSONL | **Preserve.** Append-only: prior message lines remain; a `{"$rewindTo":"<id>"}` record is appended (`appendRecord`). |
| Active conversation | **Destroy (truncate).** `rewindTo` slices messages to exclude the target id and everything after it. |

Evidence: `google-gemini/gemini-cli`
`packages/core/src/services/chatRecordingService.ts`; user docs
`docs/cli/rewind.md` (“Destructive action” for current session history).

Phase 4 capsule readers must replay `$rewindTo` markers before emitting
canonical events (already noted in `session-storage-map.md`). Vendor
semantics remove **from and including** the target id; Reinstate’s current
index reader keeps through the matching id — WP-08 must align with vendor
when building capsules.

Fixtures: `testdata/sessionindex/gemini/{macos,windows}/`.

### Grok `/compact` — rewrite active history, preserve artifacts

| Layer | Behavior |
| ----- | -------- |
| `chat_history.jsonl` | **Destroy / rewrite.** Compaction sends `ReplaceChatHistory` → `replace_chat_history` → atomic `write_jsonl` overwrite. Prior turns are not left as earlier lines. |
| `updates.jsonl` | **Preserve (append-only).** Writes a `CompactionCheckpoint` marker referencing a side file; rewind uses markers rather than truncating the file. |
| `compaction_checkpoints/` | **Preserve** compacted conversation used by the model. |
| `compaction_requests/` | **Preserve** the full pre-compact `ConversationItem` list sent to the summarizer (recovery / offline replay). |

Evidence: user guide § `/compact`; `PersistenceMsg::ReplaceChatHistory`;
`CompactionCheckpointInfo` / `CompactionRequestFile` in
`extensions/notification.rs`.

Fixture: macOS Grok session under
`testdata/sessionindex/grok/macos/sessions/...` with post-compact
`chat_history.jsonl`, `compaction_requests/` (pre-compact turns), and
`compaction_checkpoints/`.

## Escalations for executors

1. **WP-09:** Confirm at runtime whether the target OpenCode version still
   materializes `storage/message/` or only SQLite; fail closed if the file
   tree is absent.
2. **WP-08:** Align Gemini rewind inclusion boundary with vendor
   (exclude target id), not the current index-only inclusive slice, when
   emitting capsule events.
3. **WP-10:** Prefer `updates.jsonl` as restore authority; treat
   `chat_history.jsonl` as derived and possibly post-compaction.
