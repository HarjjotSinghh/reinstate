# v0.2.0-rc.1 Tagged-Artifact Acceptance Prompts

Use these prompts only after the signed `v0.2.0-rc.1` GitHub prerelease is
published and both live installer routes pin that exact tag. They specialize
the complete release-neutral prompts in
[phase-2-agent-verification-prompts.md](phase-2-agent-verification-prompts.md).

Four environment runs start independently: native macOS arm64, native macOS
amd64, native Windows amd64, and WSL2 amd64. The first and third runs execute
the complete two-device Phase 2 matrix; the second and fourth add the separate
stable-platform evidence required by `RELEASING.md`. Stable `v0.2.0` promotion
is forbidden until all four immutable reports reconcile to PASS with zero
release-blocking findings.

## Prompt 1 — Claude Code on macOS

```text
Certify the exact signed Reinstate v0.2.0-rc.1 tagged artifacts on native
macOS arm64. You are Device A's evidence owner and final coordinator.

Read AGENTS.md, docs/testing/phase-2-local-index-acceptance.md,
docs/testing/phase-2-agent-verification-prompts.md, this v0.2.0-rc.1 dispatch,
and docs/testing/results/phase-2-report-template.md completely. Execute Prompt
1 from the release-neutral prompt document in full, with these mandatory
release-candidate overrides:

- TEST_TAG is exactly v0.2.0-rc.1. Fetch tags without merging. Verify it is an
  annotated signed tag, git verify-tag succeeds against .github/allowed_signers,
  and TEST_COMMIT=git rev-parse v0.2.0-rc.1^{} is an ancestor of origin/main.
- The GitHub release must be published, non-draft, marked prerelease, and tied
  to TEST_TAG. Require checksums.txt, five platform archives, five matching
  SBOMs, and the source archive. Verify every checksum and GitHub artifact
  attestation, and inspect archive membership without executing an unverified
  file.
- Prove https://reinstate.dev/install.sh is byte-identical to the committed
  website/public/install.sh at TEST_COMMIT and pins only v0.2.0-rc.1. Install
  into a brand-new isolated INSTALL_DIR; never replace an existing user binary.
  Require the installed rein and reinstate files to be the expected alias pair,
  their SHA-256 to match the release archive/checksums, and rein version --json
  to report v0.2.0-rc.1 plus TEST_COMMIT. The source build is supplemental and
  cannot substitute for installed-artifact evidence.
- Run the full macOS Phase 2 32-row matrix against that installed binary,
  including real Claude Code and Codex resume/fork and the TTY picker. Do not
  install Gemini CLI or OpenCode solely for acceptance; record their optional
  physical rows NOT TESTED if genuinely absent.
- Use fresh controlled sessions, projects, REINSTATE_HOME, INSTALL_DIR, report
  worktree, and markers. Reusing the b952d38 development corpus is forbidden.
- Create branch test/v0.2.0-rc.1-macos-report from TEST_COMMIT and commit only
  docs/testing/results/REPORT_DATE-macos-phase2-V020RC1.md. Include the normal
  PHASE2-DEVICE-REPORT-V1 block plus tag, installed-binary SHA-256, installer
  SHA-256, release URL, and artifact-attestation results.
- Preserve all evidence and keep the PR draft/unmerged. Do not merge, tag,
  deploy, clean up, or claim stable. Pause after the Mac report until I provide
  the complete native-Windows, macOS-amd64, and WSL2 reports. Then execute
  Prompt 1 milestone M5, validate all four immutable branches from TEST_COMMIT,
  and reconcile both Phase 2 reports plus both stable-platform reports
  independently. Add a V020RC1-FINAL-RELEASE-RECONCILIATION-V1 block recording
  all four environment verdicts. Missing either supplemental report forbids
  stable promotion even if the two-device Phase 2 matrix passes.

Return exact PASS/PARTIAL/FAIL counts, report commit/branch/PR, TEST_COMMIT,
installed binary identity, failed commands with sanitized output, and every
release-blocking finding. Missing evidence is never PASS.
```

## Handoff sequence

1. Give Prompt 1 to Claude Code on native macOS arm64, Prompt 2 to Codex on
   native Windows amd64, Prompt 3 to Claude Code on native macOS amd64, and
   Prompt 4 to Codex inside genuine WSL2 amd64 at approximately the same time.
2. Let all four runs finish independently. Do not transfer partial findings.
3. Copy the three complete final reports from native Windows, macOS amd64, and
   WSL2 into the same macOS-arm64 Claude Code session that ran Prompt 1.
4. The macOS-arm64 coordinator validates all four immutable report branches,
   completes Phase 2 M5, adds V020RC1-FINAL-RELEASE-RECONCILIATION-V1, and
   returns one final tagged-artifact and stable-platform verdict.
5. Promote to stable only if that verdict is PASS, all required rows are green
   in all four environments, release blockers are zero, and every installed
   binary identifies the same signed tag commit.

Do not clean up any environment's isolated home, index, installer directory,
controlled sessions, or report worktree until the final reconciliation is
reviewed.
