# Phase 5 universal agent coverage acceptance

**Status:** contract for `v0.5.0` · **Decided by:**
[ADR 0004](../adr/0004-universal-agent-coverage.md) · **Tier vocabulary:**
[../agent-support-tiers.md](../agent-support-tiers.md)

Stable `v0.5.0` is authorized only by a dual-platform tagged-artifact run of
this matrix on Apple Silicon macOS and native Windows x64, recorded in two
device reports from
[results/phase-5-report-template.md](results/phase-5-report-template.md).

Publishing a candidate is not evidence. The reports are the evidence.

---

## What this phase claims

That Reinstate discovers, searches, and inspects sessions from a defined set of
coding agents beyond the original five, that each agent's claimed tier is
backed by committed evidence, and that no existing capability regressed.

## What this phase does not claim

- No new handoff destinations. Claude Code and Codex CLI remain the only
  targets.
- No new synced agents. Claude Code and Codex CLI remain the only agents
  `push` and `pull` carry.
- No cross-agent transcript translation, at any tier, ever.
- No configuration support. That is Phase 6.

A device report that demonstrates a capability outside this list has tested the
wrong thing.

---

## Evidence policy

1. **The matrix is computed, not fixed.** Core rows are constant. Per-agent
   rows are derived from each agent's declared tier in the catalog. The
   candidate's row count is generated by
   `rein doctor --agents --acceptance-matrix` and recorded in the report
   header. A report whose count disagrees with the candidate's catalog is
   invalid.
2. **`PARTIAL` and `NOT TESTED` do not pass a required row.** A missing
   required result is `FAIL`.
3. **An agent the tester does not have installed is not a `FAIL`** — it is a
   scope reduction. The agent's tier drops to the highest tier both platforms
   could verify, in the candidate, before stable. Tiers are never claimed on
   one platform's evidence.
4. **No real transcripts, prompts, responses, credentials, private paths,
   repository names, or raw child-process output** appear in a report. The
   redaction rules in [agent-storage-probe.md](agent-storage-probe.md) apply to
   reports as well as to probes.
5. **Reports are append-only.** Preserve failures; add targeted rechecks as new
   evidence rather than editing a prior result.

## Required environments

| Requirement | Value |
| ----------- | ----- |
| Platform 1 | Apple Silicon macOS, native arm64 process |
| Platform 2 | Native Windows x64, not WSL |
| Toolchain | Go 1.25.13 |
| Artifact | Installed from the signed candidate tag, verified against checksums and attestations |
| Index state | A rebuilt index, so discovery is exercised rather than replayed from a stale database |

WSL2 is optional and, when tested, is recorded as a third device rather than as
part of the Windows report. Native Windows and WSL2 are different devices with
different agent trees.

---

## Required agent installs

Claude Code, Codex CLI, Gemini CLI, OpenCode, and Grok Build must be present on
both platforms, because Matrix G proves they did not regress.

Every candidate agent claiming T1 or higher must be present, used in at least
two distinct projects, and used enough to produce more than one session. An
agent with one session does not exercise ordering, project attribution, or
search.

Do not install an agent solely to pass a row and then delete it. The tier is a
claim about real usage.

## Matrix A — Catalog integrity (required, both platforms)

| # | Assertion |
| - | --------- |
| A1 | Every catalog descriptor validates at process start; no duplicate or empty keys |
| A2 | `rein doctor --agents` lists every catalog agent, including every T0 agent |
| A3 | Each T0 agent shows a machine-readable reason from the closed enumeration |
| A4 | Declared tier and present capability constructors agree for every agent |
| A5 | Every `Evidence` path in every descriptor exists in the tagged tree |
| A6 | `rein sessions --agent <key>` accepts exactly the T1+ keys and rejects others with exit `2` |
| A7 | `rein resume` accepts exactly the T3+ keys and refuses others with exit `5` and a reason |
| A8 | Agent order in all output is deterministic across runs |
| A9 | A descriptor with a deliberately broken evidence path fails the conformance suite |
| A10 | No catalog agent's scan writes, renames, or locks any file under an agent root |

A10 is verified with a filesystem audit during a full index refresh, not by
inspection.

---

## Matrix B — Probe and redaction (required, both platforms)

| # | Assertion |
| - | --------- |
| B1 | `rein doctor --agents --json` conforms to `AGENT-PROBE-V1` |
| B2 | Output contains no absolute path, home directory name, or username |
| B3 | Output contains no JSON value from any session file, only keys |
| B4 | Directory and file names are shape-normalized, with no raw UUID, hash, or path slug |
| B5 | No excluded subtree, including credential and cache paths, appears anywhere in output |
| B6 | Probe against an agent that is absent reports absence without error |
| B7 | Probe against a root that exists but is empty is distinguishable from an absent root |
| B8 | `scripts/testing/agent-storage-probe.sh` and `.ps1` produce output identical to the binary |
| B9 | The fixture secret scanner passes over every committed probe artifact |

## Matrix C — Per T1 agent (required, both platforms)

Six rows per agent at T1 or above.

| # | Assertion |
| - | --------- |
| C1 | `rein sessions --agent <key>` lists real sessions from at least two distinct projects |
| C2 | Project, branch, title, timestamp, and message count match what the agent shows |
| C3 | `rein search` finds a known string from a real session by prompt, and by file when the agent records files |
| C4 | `rein inspect <key>:<id>` returns bounded metadata and prints no transcript body |
| C5 | Below T3, every record reports a read-only reason, and resume is refused with exit `5` |
| C6 | A corrupted final record, an empty root, and an absent root each degrade cleanly with no panic and no partial record |

C6 is exercised against a **copy** of the tree or a synthetic fixture. Never
corrupt a tester's real agent data.

---

## Matrix D — Per T2 agent (required, both platforms)

Five rows per agent at T2 or above.

| # | Assertion |
| - | --------- |
| D1 | `rein handoff --from <key>:<id> --to claude --dry-run` produces a capsule and a fidelity report |
| D2 | The capsule contains no content the source did not contain, and no invented turn |
| D3 | Unknown records are `referenced` or `omitted` with a reason, never guessed |
| D4 | A truncated source produces a boundary at the last complete record, with offset and hash recorded |
| D5 | Two runs over an unchanged source produce byte-identical capsules |

---

## Matrix E — Per T3 agent (required, both platforms)

Six rows per agent at T3.

| # | Assertion |
| - | --------- |
| E1 | `rein resume <key>:<id>` launches the vendor CLI and the real session continues |
| E2 | The resumed session is the requested one, verified inside the agent |
| E3 | `rein fork` produces a distinct session when the vendor supports forking |
| E4 | A version below the supported minimum, and one above the maximum, both yield exit `5` naming the range |
| E5 | An active session for that agent is detected and resume is refused or warned per policy |
| E6 | Non-interactive invocation exits `7` rather than launching blind |

E1 and E2 are physical journeys. A parser test is not evidence for this matrix.

## Matrix F — Per T0 agent (required, both platforms)

Two rows per agent at T0.

| # | Assertion |
| - | --------- |
| F1 | The agent appears in `rein doctor --agents` with its reason |
| F2 | No command offers a capability for it, and no output implies one is coming |

## Matrix G — No regression (required, both platforms)

| # | Assertion |
| - | --------- |
| G1 | Claude Code and Codex CLI native resume and fork behave as in `v0.4.0` |
| G2 | Claude to Codex and Codex to Claude structured handoff both complete |
| G3 | Gemini, OpenCode, and Grok remain handoff sources and remain read-only |
| G4 | `rein push` and `rein pull` carry Claude and Codex sessions, and no other agent's |
| G5 | Path remapping across macOS and Windows is unchanged |
| G6 | Existing exit-code semantics are unchanged; no new exit codes were introduced |
| G7 | An index built by `v0.4.0` upgrades without data loss, or migrates with an explicit message |
| G8 | Capsules remain excluded from sync |

G7 matters: users will upgrade over an existing index. A silent schema change
that empties someone's index is a release blocker.

---

## Matrix H — CLI contract and performance (required, both platforms)

| # | Assertion |
| - | --------- |
| H1 | `docs/cli-reference.md` matches the shipped flags, enforced by `internal/doctest` |
| H2 | `--json` output for `sessions`, `search`, `inspect`, and `doctor` matches its documented shape |
| H3 | Full index refresh across all installed agents completes within the documented ceiling |
| H4 | Refresh with no changes is materially faster than a cold refresh |
| H5 | A single unreachable or slow agent source does not block the others |
| H6 | Shell completion lists the correct agent keys per command |

H5 is the practical risk of breadth: one agent with a large tree or a hung
subprocess must not make `rein sessions` unusable.

## Reporting

Two device reports, one per platform, at:

- `docs/testing/results/<DATE>-macos-phase5-<CANDIDATE>.md`
- `docs/testing/results/<DATE>-windows-phase5-<CANDIDATE>.md`

Each is committed on its own branch, and each device report is immutable once
its terminated device block is committed. Only the macOS coordinator report may
add the final reconciliation block, and only after independently verifying both
device-report commits.

## Candidate dispatch

Dispatch a candidate only after the live installers pin its exact tag. Both
platforms then run this matrix against the installed tagged artifact. Stable
`v0.5.0` is authorized when both reports are `PASS` with zero release-blocking
findings, and when every tier claimed in the shipped catalog is backed by rows
that passed on both platforms.

If one platform verifies an agent and the other cannot, the agent ships at the
lower tier. It does not ship at the higher tier with a footnote.
