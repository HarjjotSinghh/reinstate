## 12. Upgrade path

The row-level and source-level change detection in releases before this
candidate could not tell that Reinstate itself had changed, so an existing index
was never re-read and a reader fix reached nobody. This is invisible to a clean
run, so it was exercised deliberately.

An index built by the previous release, then opened by the tagged binary: 3 Gemini sessions with 0 resolved workspaces became 3 sessions with 3 resolved, with no row lost. A second run stayed warm at the same counts, and the previous release could still reopen the upgraded index.

## 13. Findings and dispositions

No release-blocking findings.

B4 is genuinely exercised on this device: the OpenCode root contains Git object stores holding loose objects, and the probe renders those names as a length token with zero raw hex runs. The predecessor candidate failed this row here, which is why this candidate exists.

Three harness defects were corrected during this run and are recorded in the candidate dispatch so a later run does not repeat them: a version shim written in a form this platform never executes, a range assertion pinned to specific versions rather than to the message naming a range, and a filesystem audit that attributed a concurrently running agent's writes to the refresh.
