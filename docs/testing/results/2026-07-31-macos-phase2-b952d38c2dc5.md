## 12. Findings

### Release-blocking

None.

### Non-blocking

1. **Child exit code is normalized, not passed through.** A native child that
   exits `7` surfaces as `rein` exit `1` (`ExitRuntime`). This is the
   documented contract — raw pass-through would collide with Reinstate's stable
   codes (`Safety = 7`) — but callers cannot recover the vendor's exact status.
   Worth stating explicitly in user documentation.
2. **`files` is omitted rather than empty in `sessions --json`.** Records with
   no known file references omit the key entirely instead of emitting an empty
   array, which makes naive JSON consumers key-error. Cosmetic; the `--file`
   filter itself is correct.

### Test-harness deviations

1. **Nested-agent environment markers had to be cleared.** Because this run was
   driven from inside a Claude Code session, the launched vendor child
   inherited `CLAUDE_CODE_CHILD_SESSION` (and sibling `CLAUDE_CODE_*` markers)
   and disabled its own transcript saving, printing *"Transcript saving is off
   — inherited CLAUDE_CODE_CHILD_SESSION marker"*. Under that condition the
   Claude fork produced no new session file. Re-running the same `rein` command
   with only those inherited markers unset — no Reinstate flag changed, no
   sandbox or approval control disabled, no vendor file touched — produced the
   correct vendor-native behavior. This is a harness artifact of running
   acceptance inside an agent session, not Reinstate behavior. Both the
   affected Claude resume and fork gates were re-run to completion and are
   reported on the clean-environment runs only.
2. **First Claude PTY launch consumed one scripted input.** Claude Code's
   one-time "do you trust this folder" prompt absorbed the first scripted
   keystroke on the very first launch in the disposable project. That attempt
   was discarded and the gate re-run after the folder was trusted; only the
   completed run is reported.
3. **Codex TUI echoes input character-by-character**, so the challenge marker
   does not appear as a contiguous string in the raw PTY capture. Verification
   used the persisted vendor record (assistant-role field) instead, which is
   stronger evidence.
4. **Ambiguous-bare-ID and read-only exit-`5` gates were satisfied by the
   deterministic injected-record tests**, as the runbook permits, because
   manufacturing them physically would require altering a real vendor session
   file or installing an absent vendor.

No deviation was converted into a `PASS` without re-running the gate to
completion.
