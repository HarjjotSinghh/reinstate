## 12. Findings

### Release-blocking

1. The installed, attested RC1 binary fails the explicit full-commit identity
   requirement. It reports only the seven-character `e458e8e` because the
   release configuration injected the short commit. Stable promotion is
   blocked even though the short value resolves uniquely in this repository.

### Non-blocking

1. The default `rein sessions` listing is capped at 100 records. This did not
   affect any gate, but the cap is not stated in the command's help text.

### Test-harness deviations

1. **Inherited `CLAUDE_CODE_CHILD_SESSION`.** Because Device A's operator is
   itself Claude Code, the first Claude resume attempt inherited
   `CLAUDE_CODE_CHILD_SESSION`, which disabled transcript saving in the child and
   prevented the controlled marker from persisting. This is harness
   interference, **not** a Reinstate defect — Reinstate had already launched the
   correct vendor in the correct workspace with the correct session history. The
   variable was cleared for all subsequent resume/fork gates, after which every
   marker persisted. Rows 20, 22, and 26 are marked PASS only on the basis of
   the runs with the variable cleared.
2. **Claude Code first-run folder-trust prompt.** On a freshly created
   workspace, Claude Code displays a trust prompt that consumed the first
   scripted input. Retried with the prompt acknowledged. Not a Reinstate defect.
3. Rows 28 and 29 are `NOT TESTED` because Gemini CLI and OpenCode are genuinely
   absent; neither was installed solely for acceptance, per the dispatch.

No deviation was silently converted to `PASS`.
