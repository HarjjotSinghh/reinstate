# v0.2.0 limited-platform stable release decision

Decision: `APPROVED_WITH_LIMITED_PLATFORM_SUPPORT`

Date: 2026-08-05

This decision authorizes stable `v0.2.0` support on exactly two platforms:

- Apple Silicon macOS (`darwin/arm64`); and
- native Windows x64 (`windows/amd64`).

The following published packages are preview and unverified for `v0.2.0`:

- Intel macOS (`darwin/amd64`);
- native Linux (`linux/amd64` and `linux/arm64`); and
- WSL2 (`linux/amd64` package in a genuine WSL2 environment).

Installer availability is not a stable-support claim for a preview platform.
WSL1 remains unsupported.

## Runtime-equivalence gate

Stable promotion does not infer new runtime behavior from release packaging.
Before tagging, compare the RC2 tree with the proposed stable tree:

```sh
git diff --name-only \
  8dd6073118131dd4ecacfca3eb1cde3f07df5eb6..HEAD \
  -- cmd internal go.mod go.sum \
  | grep -v '^internal/doctest/'
```

The required result is empty. At this decision's reviewed base
`e524d9c73ad27591c47e43534fccc1d9b43e9997`, only release-documentation and
`internal/doctest` distribution-contract tests differ in that scope. The
stable release commit must preserve this empty runtime diff.

The stable tag still requires its own green merge gates, signed annotated tag,
checksums, SBOMs, source archive, attestations, archive-membership checks,
installed full-commit identity, and live installer-pin verification. RC2
artifact checks are not substituted for those stable distribution checks.

## Explicit waiver

The normal release runbook requires macOS arm64, macOS amd64, native Windows
amd64, and WSL2 amd64. For `v0.2.0` only, the maintainer explicitly waived the
missing Intel Mac and WSL2 physical runs and chose a narrower stable-support
claim instead of fabricating certification.

- Intel Mac follow-up: [#97](https://github.com/HarjjotSinghh/reinstate/issues/97)
- WSL2 follow-up: [#98](https://github.com/HarjjotSinghh/reinstate/issues/98)

This waiver does not carry forward automatically. A later stable release must
either satisfy its declared matrix or record a new, release-specific decision.
