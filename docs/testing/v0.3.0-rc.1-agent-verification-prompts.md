# v0.3.0-rc.1 tagged-artifact acceptance prompts

Use these prompts only after the signed `v0.3.0-rc.1` GitHub prerelease is
published and both live installer routes pin that exact tag. They specialize
the release-neutral [Phase 3 acceptance contract](phase-3-verified-resume-acceptance.md)
and use the [Phase 3 report template](results/phase-3-report-template.md).

Two mandatory device runs start independently and may run in parallel:

1. Apple Silicon macOS (`darwin/arm64`); and
2. native Windows x64 (`windows/amd64`, never WSL).

These two reports decide RC1 tagged-artifact acceptance. They do not satisfy
or authorize the separate stable promotion decision and fresh stable
validation on the same two supported platforms. Intel macOS and WSL2 are
unsupported/unverified optional evidence; their absence or failure does not
block RC1 or stable `v0.3.0`, and neither may be claimed as supported from built
artifacts alone.

## Fixed RC1 performance corpus and ceilings

Run the checked-in `scripts/testing/phase3perf` harness from the exact tagged
source checkout. Its embedded `phase3perf-v1` specification has canonical
digest `4bf0b653ce76dcc3f7dd93916399bfdea8b658e1fbe41a9423608f2e7a6f8a76`.
The harness refuses a source checkout whose HEAD is not `TEST_COMMIT` or whose
harness differs from that commit. Run it once, with a new absolute private
evidence root, the absolute installed alias paths, the literal full commit, and
an operator-curated PATH:

```text
go run ./scripts/testing/phase3perf run --root ABS_NEW_EVIDENCE_ROOT --rein ABS_INSTALLED_REIN --reinstate ABS_INSTALLED_REINSTATE --source-root ABS_TAGGED_SOURCE --expected-commit TEST_COMMIT --expected-version 0.3.0-rc.1 --path CURATED_PATH
```

`CURATED_PATH` contains only non-empty, absolute, clean, canonical physical
directories outside the source checkout and evidence root. It must resolve
trusted Git, Claude, and Codex executables plus the separately supplied
installed aliases, and must not resolve OpenCode. Do not add a wrapper, source
build, generated fixture directory, or evidence-owned executable. OpenCode
omission is deliberate so results have one exact `agent_not_installed` warning;
the empty Gemini home produces no records. Any ambient managed capability,
unexpected result, dirty workspace, executable ambiguity, or missing dependency
fails closed. Do not bypass it or mutate generated bytes.

The normal corpus is exactly four Claude plus four Codex records and sixteen
capability names. The synthetic large corpus is exactly 1,000 bounded session
metadata records: 500 Claude and 500 Codex, plus exactly 256 capability names,
each bounded. Each record has exactly four events, two counted messages, and
two file references. The frozen byte widths are 36-byte IDs, 64-byte titles,
160-byte user metadata, 64-byte assistant metadata, two 14-byte file paths, and
32-byte capability names. Timestamps start at the embedded UTC base and advance
one second per agent record. Limits are 100 and 1,000, while counts are eight
and 1,000; the fixed anchors at indices two and 250 therefore remain visible.
Each corpus gets its own isolated agent/process/Reinstate homes and a clean,
remote-free `main` Git workspace whose frozen SHA-1 HEAD is
`697ed29583a03045783557c3e8aeec92d9f7f01c`.

The timed executable is the installed `rein` alias. `reinstate` is not timed:
the harness runs the complete command set once through both aliases and requires
equal exits and normalized JSON. It also times installed `rein version --json`
and `rein --help` as separate startup rows: three fresh-home cold samples, then
one warmup and twenty warm samples. Version must report `0.3.0-rc.1` plus the
literal full `TEST_COMMIT`; help must retain the required command surface and
normalized alias parity.

For each corpus, substitute its frozen literal values into the following exact
installed-artifact commands. Preserve command and flag order; pass each query
or reference as one shell argument. Warning acknowledgements, extra filters,
combined commands, in-process benchmarks, and source builds are forbidden:

```text
rein sessions --limit CORPUS_LIMIT --json
rein search CORPUS_QUERY --limit CORPUS_LIMIT --json
rein inspect CORPUS_CLAUDE_REF --json
rein resume CORPUS_CLAUDE_REF --dry-run --json
rein resume CORPUS_CODEX_REF --dry-run --json
rein fork CORPUS_CLAUDE_REF --dry-run --json
rein fork CORPUS_CODEX_REF --dry-run --json
```

Before timing, require every corpus command to exit zero, parse as JSON, select the
expected controlled records/plans, and leave every controlled source
fingerprint unchanged. Run with no live writer to either corpus. Warm timing is
twenty sequential, independent process-start-to-exit samples for **each** of
the seven commands in each corpus (140 warm samples per corpus). Record a
separate median, p95, maximum, timeout count, and result-validation status for
every logical command. Never pool inspect or dry-run results.

Cold timing is three independent samples per corpus of only the first command.
Before each sample, close all Reinstate processes using the isolated
`REINSTATE_HOME`. Following the safe manual-reset procedure in
[`troubleshooting.md`](../troubleshooting.md), move only these possible derived
files from `REINSTATE_HOME/cache/` into a distinct private evidence directory:

```text
session-index-v2.sqlite
session-index-v2.sqlite.lock
session-index-v2.sqlite.write.lock
session-index-v2.sqlite-journal
session-index-v2.sqlite-wal
session-index-v2.sqlite-shm
```

Never delete them, use a wildcard, move another home entry, or touch a vendor
source. Confirm the entire listed v2 family is absent, then time one fresh
`rein sessions --limit CORPUS_LIMIT --json` process and validate its result.
Preserve all three moved families through reconciliation. After the last cold
sample, one untimed successful refresh may establish the warm state.

The harness captures bounded stdout/stderr in memory, validates it, and discards
the raw bytes. It uses a monotonic process-start-to-exit clock, a 30-second
timeout, one warmup, twenty warm samples, and nearest-rank p95. It fingerprints
every generated source/capability/workspace file plus mtime before and after.
Store `results.json` privately; commit only its sanitized aggregates and
digests.

| Corpus/mode | Apple Silicon macOS release-blocking ceiling | Native Windows x64 release-blocking ceiling |
| ----------- | -------------------------------------------- | -------------------------------------------- |
| Startup `version --json` and help, each cold | maximum `4s` | maximum `8s` |
| Startup `version --json` and help, each warm | p95 `2s` | p95 `4s` |
| Normal, each warm command independently | p95 `2s` | p95 `4s` |
| Normal cold `sessions --limit 100 --json` | maximum `8s` | maximum `12s` |
| Large, each warm command independently | p95 `4s` | p95 `8s` |
| Large cold `sessions --limit 1000 --json` | maximum `12s` | maximum `18s` |

Fingerprint the controlled vendor sources before and after each corpus. Source
mutation, alias mismatch, failed JSON/result validation, any timeout, unbounded
command/file growth, an observed 20–30 second regression, or a greater than 25 percent comparable same-host p95 regression for any command is release
blocking even if an absolute ceiling passes. If no comparable Phase 3 baseline
exists, record that comparison as unavailable; never manufacture a pass. Raw
JSON, raw sample logs, transcripts, source content, and private paths remain
uncommitted; reports contain only controlled references, counts, aggregates,
and sanitized bounded diagnostics.

## Handoff and reconciliation sequence

1. Start both prompts independently from the same exact `TEST_COMMIT`.
2. Each owner makes only additive commits on its device-owned report branch;
   no force-push, amend, product edit, or cross-device corpus transfer is
   allowed.
3. Give the complete Windows report commit to the existing macOS coordinator.
4. The coordinator fetches only the report ref, verifies both branches start at
   `TEST_COMMIT`, and proves every base-to-tip change is confined to the one
   allowed report path.
5. The coordinator recalculates all counts, privacy checks, performance
   verdicts, blocking findings, and supersessions without trusting labels.
6. The coordinator appends one
   `PHASE3-RC1-FINAL-RECONCILIATION-V1` block and terminator to the macOS report.
   The terminator is exactly `END-PHASE3-RC1-FINAL-RECONCILIATION-V1`.
   `rc1_tagged_artifact_acceptance=PASS` requires both devices to have 32 PASS,
   zero required PARTIAL/FAIL/NOT TESTED, zero release blockers, and passing
   privacy/repository checks.
7. Keep both PRs draft and unmerged until a separate maintainer decision.
   Stable `v0.3.0` remains unauthorized because RC1 acceptance is not a stable
   promotion decision and fresh stable validation on both supported platforms
   remains outstanding. Intel macOS and WSL2 evidence is optional and never a
   stable blocker.
