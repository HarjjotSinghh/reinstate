# `v0.6.0` native Windows acceptance

The acceptance contract for `v0.6.0` candidates and the stable promotion,
under the Windows-first waiver in
[ADR 0005](../adr/0005-v0.6.0-scope-and-windows-first-acceptance.md). It
composes three existing contracts into one Windows column and records, in
section E, every row those contracts require on Apple Silicon macOS that this
release defers.

It extends and does not replace:

- [Phase 5 universal agent coverage](phase-5-universal-agent-coverage-acceptance.md)
  — the generated matrix, which carries Phases 1–4 as its no-regression rows;
- [`v0.5.2` CLI experience](v0.5.2-cli-experience-acceptance.md) — the 22
  interactive rows;
- hosted ticket #16 — Windows parity for every Hop journey, given rows here
  for the first time.

## Evidence policy

The Phase 3 and Phase 5 policies apply unchanged, plus:

- **Never point a bench at the developer's real agent trees or the shared
  checkout.** Throwaway projects under `D:\ReinstateAcceptanceProjects\`,
  isolated Reinstate homes, `scripts/tuisandbox`, and your own worktree.
- **Real vendor binaries for resume, handoff, and sync rows.** A dry-run
  launch plan is evidence of the plan; a row that says "resume" needs the
  resumed session to answer from history at least once per agent per run.
- **Check the harness before the product.** A row that passes without
  exercising its mechanism is `FAIL`. `v0.5.0-rc.6` recorded false passes for
  exactly this reason.
- **A `PASS` names the platform.** Nothing in a `v0.6.0` report, data file,
  or release note implies macOS.
- **Real vendor runs use an isolated agent home.** Sessions for resume,
  fork, handoff, and sync rows are created by the vendor binary in a
  throwaway project with the vendor's own home variable pointed at an
  isolated directory, seeded with nothing but the credential file the vendor
  needs to run. The one exception is a T1 discovery row (`C1`–`C4`), whose
  definition is the discovery of sessions the vendor already holds: those
  run through `rein` alone, read-only, against the host's real root, and the
  report records counts and field names only, never a title, prompt, path,
  or identifier from a session the run did not create.

## Required environment

Native Windows 11 x64 (`windows/amd64`), never WSL, provisioned per
[windows-acceptance-host.md](windows-acceptance-host.md) including its Hop
lab and ConPTY driver sections. Windows PowerShell 5.1 for the report shell;
Git Bash for the POSIX scripts. Go `1.25.13` via `GOTOOLCHAIN`. GoReleaser,
Syft, and MinGW `gcc` on `PATH`.

Required installs at the versions the candidate verifies (the release commit
records them; re-check immediately before the run): Claude Code, Codex CLI,
OpenCode. Optional, never installed solely for a row: Grok Build, Qwen Code,
Gemini CLI, Kimi Code CLI, Copilot CLI, Cursor CLI, Cline, Pi.

## Artifact identity

- **Pre-tag run** (candidate branch): a GoReleaser snapshot of the exact
  release-candidate commit, staged by `scripts/stage-release-assets.ps1`,
  checked by `scripts/check-release-artifacts.ps1`, installed by
  `scripts/test-install.ps1` into a fresh directory. Evidence for the PR;
  authorizes nothing.
- **Tagged-artifact run**: the signed `v0.6.0-rc.N` prerelease installed from
  the live bootstrap after proving it pins that exact tag, per the candidate
  dispatch. This is the run that authorizes stable.

Either way: `rein` and `reinstate` byte-identical; `rein version --json`
names the tag (or `0.0.0-…-SNAPSHOT-…` for the pre-tag build) and the full
commit.

## C — CLI experience (required)

The 22 rows of the `v0.5.2` contract, Windows column, through the ConPTY
driver against `scripts/tuisandbox`. Rows 2 and 22 compare byte-for-byte
against a `v0.5.1` binary installed from the GitHub release. Row 21 (ASCII
glyph fallback on legacy conhost) is Windows-only and required.

**Row 22, as it applies to `v0.6.0`.** The `v0.5.2` contract wrote "every
`--json` document is byte-identical to `v0.5.1`" for a candidate that only
added a terminal UI. This candidate also carries engine changes the
changelog names, and those change documents on purpose. Row 22 therefore
reads: every `--json` document is byte-identical to `v0.5.1` **except for
differences that a `[0.6.0-rc.1]` or `[0.5.2-rc.1]` changelog entry
describes**, and the report lists every difference beside the entry that
explains it. Known, accepted differences at this candidate:

- `sessions --json` capability fields for Grok Build, OpenCode, and Qwen
  Code sessions (tier promotions; `[0.5.2-rc.1]` and `[0.6.0-rc.1]`);
- the `agent.active` check in `resume --dry-run --json` and
  `inspect --json` (active-session detection on the resume path;
  `[0.5.2-rc.1]`).

A difference with no changelog entry fails the row. Claude Code and Codex
documents on a home that holds no other agent's sessions must still be
byte-identical apart from the `agent.active` check.

## Reporting

One device-owned report per run:

- `docs/testing/results/YYYY-MM-DD-windows-v060rcN-pretag.md` (pre-tag);
- `docs/testing/results/YYYY-MM-DD-windows-v060rcN.md` (tagged artifact);
- `docs/testing/results/YYYY-MM-DD-windows-hop-parity-v060.md` (section D,
  may be shared by the pre-tag and tagged runs if re-run against the tagged
  binary and both identities are recorded).

Use the Phase 5 template's structure, then a section C table, a section D
table, and section E copied with every row `DEFERRED`. `PARTIAL` and
`NOT TESTED` do not pass a required row; a missing required result is `FAIL`.
Cumulative and append-only: a `FAIL` that later passes keeps both entries and
says what changed.

The device verdict block must state, separately: the total row count; the
required row count (total minus every `N/A (definitional)` row); the
`N/A (definitional)` rows, listed; the `NOT TESTED (host credential)` rows,
listed; and the `PASS` count over the required rows. At planning time that
is **216** rows total (178 + 22 + 16), of which `opencode:D4` is
`N/A (definitional)` — **215** required.

## Dispositions that do not block the device verdict

Two narrow row dispositions are recorded outside the `PASS`/`FAIL`/
`PARTIAL`/`NOT TESTED` verdict a required row otherwise needs, so that a row
neither the product nor the operator can make pass does not block a
Windows-first stable indefinitely. Both must be named in the report; neither
is invented silently.

- **`N/A (definitional)`** — a row whose mechanism cannot exist for that
  agent's store layout at all, regardless of fix or credential. Today this
  is exactly `opencode:D4`: OpenCode's SQLite-only store has no JSONL record
  boundary to truncate, so the partial-final-record mechanism the row tests
  has nothing to apply to. Recorded `N/A (definitional)` with the reason,
  and **excluded from the required row count** — it is not counted toward
  either the denominator or the `PASS` numerator. The report must list every
  such row explicitly; a row is never silently dropped from the table.
- **`NOT TESTED (host credential)`**, optional agents only — a row for an
  agent this contract lists as optional (`Required environment`, above:
  Grok Build, Qwen Code, Gemini CLI, Kimi Code CLI, Copilot CLI, Cursor CLI,
  Cline, Pi) that cannot complete because the host's vendor credential for
  that agent is expired or absent. Recorded `NOT TESTED (host credential)`
  with the reason, and **does not block the device verdict**, provided both:
  (1) the same row is `PASS` for every *required* agent (Claude Code, Codex
  CLI, OpenCode), and (2) the same row is `PASS` for at least one *other*
  optional agent at the same tier (for `qwen:E1`/`E2`/`E3`/`E5` at T4, that
  is `grok`). The report must name every row recorded this way and the
  credential it depends on. A row recorded `NOT TESTED (host credential)` is
  still counted toward the required denominator — it is a disposition on an
  otherwise-required row, not an exclusion from it — but does not by itself
  fail the verdict when the two conditions above hold.
- **Everything else** — any row not matching one of the two dispositions
  above keeps the existing rule: `PARTIAL` and `NOT TESTED` do not pass a
  required row, and a missing required result is `FAIL`.

## Run notes

- **Host environment (2026-09-06).** The acceptance host carried persistent
  user-level `REINSTATE_BACKEND=memory` and `REINSTATE_MEMORY_BACKEND_DIR`
  variables from earlier lab work; `rein` honours `REINSTATE_BACKEND` before
  it reads the profile, so every Hop command silently used a local store and
  the control plane saw no requests. Both were removed from the user
  environment on 2026-09-06; a run still `unset`s them defensively and says
  so. The host's `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, and `XDG_DATA_HOME` are
  its **live** agent homes, not contamination: leave them as they are.
  Unsetting `CLAUDE_CONFIG_DIR` sends a spawned Claude Code run to a stale
  `~/.claude` whose sign-in cannot refresh, which is what left the Claude
  resume rows at PARTIAL in the pre-tag report. Isolate a row with your own
  value for the vendor's home variable instead of unsetting the host's.
- **Process enumeration (2026-09-06).** During the pre-tag passes
  `Get-CimInstance Win32_Process` and `tasklist` failed on this host with
  "Critical error", which is how the active-session fail-safe defect was
  found. An elevated `winmgmt /verifyrepository` later reported the
  repository consistent and non-elevated enumeration works again, so the E5
  rows are runnable on the tagged artifact.
- **Windows-only website test failures.** `website/src/lib/api-routes.test.ts`
  (SQLite file still locked when the test unlinks it) and
  `website/src/lib/repository-social-preview.test.ts` (PNG bytes are not
  reproducible with this host's font stack) fail on native Windows and pass
  on the Linux CI runner. They are not release rows; note them, do not count
  them.
- **Release-truth guards move together.** `product.currentRelease`,
  `compatibility.json`, `CITATION.cff`, the public bootstraps, and the CI
  installer-verification pin are checked against each other by
  `internal/doctest`; a branch that moves one without the rest fails the doc
  gate until they are merged together.
- **Preflight and adapter wall-clock guards** were widened for a loaded host
  in W2 and by the coordinator; a report that still sees them fail under a
  parallel full suite should re-run the package alone and record both
  results.
- **`MatrixH:H7` lab isolation, corrected (2026-09-07,
  [#424](https://github.com/HarjjotSinghh/reinstate/issues/424)).** The
  `v0.6.0-rc.4` dispatch's "fresh lab account" wording for `H7` was
  ambiguous and was read by that run's executor as a **fresh Windows user
  account**, which needs administrator rights to create and could not be
  set up, so the row was abandoned before its own UAC prompt was reached.
  The contract rule, precisely:
  - **"Fresh Hop lab account"** means a new **Hop** account created through
    the lab's `hopd` (`hoplab pair init`, or the `rein account init` flow
    against the lab control plane) that has had **zero sessions pushed to
    it** — not a new Windows OS user account. Creating it needs no
    elevation beyond the row's own single UAC prompt for the daemon
    install/elevation step; it does not require a new Windows login.
  - Before the round trip, record a **before** listing digest of each of
    the live `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, and `XDG_DATA_HOME` roots
    (path + size per file, sorted, SHA-256 of the list); record the same
    **after** the round trip. All three before/after digest pairs must be
    byte-for-byte identical — a mismatch is `#424` recurring and blocks the
    row regardless of whether the daemon mechanism otherwise worked.
  - The operator go-signal file `D:/ReinstateAcceptanceProjects/h7-go.txt`
    is polled every **60 seconds**, for **up to 150 minutes**, starting
    only after every other row in the executor's part is already done (not
    in parallel with them). `PARTIAL` (operator/harness availability) is
    recorded only once that full wait has elapsed with no go-ahead — a
    shorter poll window is not a basis for `PARTIAL`.
