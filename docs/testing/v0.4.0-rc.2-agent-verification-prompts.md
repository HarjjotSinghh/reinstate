# v0.4.0-rc.2 tagged-artifact acceptance prompts

Use these prompts only after the signed `v0.4.0-rc.2` GitHub prerelease is
published and both live installer routes pin that exact tag. They specialize
the release-neutral [Phase 4 acceptance contract](phase-4-cross-agent-handoff-acceptance.md)
and use the [Phase 4 report template](results/phase-4-report-template.md).

`v0.4.0-rc.2` carries the same Phase 4 surface as `v0.4.0-rc.1` — canonical
capsules, five source readers, Claude Code and Codex destinations, the
model-free handoff pipeline, local private lineage, the full CLI surface,
synthetic fixtures, adversarial tests, and documentation — plus corrective
fixes for what rc.1 physical acceptance found. Publication means ready for
physical acceptance; it does not mean acceptance passed. Current stable remains
`v0.3.0`, and stable `v0.4.0` requires a later promotion decision and fresh
validation.

A structured handoff starts a **new** destination session that continues the
same task. It is not a cross-agent resume, not the same session, not lossless,
and not full context. Report it that way in every row and every summary.

## Why RC2 exists

**`v0.4.0-rc.1` was published and its dual-platform physical acceptance
FAILED.** It is a real, tagged, public prerelease whose verdict is on record;
nothing here retracts that. Six defects are fixed since, and the rc.2 run must
**re-verify** them rather than rediscover them:

1. **Claude source probe (`efc8367`).** Version probing required an
   `<agent-root>/version` file that real Claude Code installations never
   create. It resolved to "unknown", fell outside the verified range, and every
   Claude-sourced handoff exited `5` with `source agent "claude" is UNTESTED` —
   while `rein inspect` called the same agent supported in the same invocation.
   Version now resolves through `internal/agentcheck`, the same probe `inspect`
   reports. Claude and Codex readers share one documented contract:
   unrecognized layout → `UNSUPPORTED`; version determinable and in range →
   `SUPPORTED`; determinable and out of range → `UNTESTED`; not determinable →
   `SUPPORTED` on layout alone, because a handoff must work when the source
   agent is closed, logged out, rate limited, or uninstalled.
2. **Reader path tokenization (`efc8367`).** Readers lifted absolute paths out
   of tool inputs, tool results, and attachment references, and capsule
   validation correctly rejected them. Paths are now tokenized at the reader
   boundary; a path outside every configured root becomes
   `${EXTERNAL:<digest>}/<basename>` — stable and comparable, never a location.
3. **`changed_files` (`84c635d`).** The porcelain parser kept its counts and
   discarded the pathnames, and the pipeline then read a test-only option field
   and wrote the empty result back over the bound workspace. Every handoff told
   the destination `Changed files: (none)`, even over a dirty working tree.
4. **Version-probe timeout (`84c635d`).** A two-second probe that **timed out**
   was reported identically to an absent agent, and the reader contract answers
   an absent agent with `SUPPORTED`. A determinable, out-of-range agent was
   therefore accepted silently whenever the machine was briefly busy. This is
   production-reachable fail-open under load, not a test artifact: agent CLIs
   are language runtimes. Timeouts now classify as `UNTESTED` and retry once
   with a larger budget.
5. **Prose versus path (`3712b4c`).** Capsule canonicalization applied the
   absolute-path predicate lexically to every string, so any value beginning
   with `/` aborted the handoff — including `/init do the thing`, which is a
   user message. The check is now structural and visits path-typed fields only.
6. **Claude ceiling (`9be1d63`).** Widened through `2.1.229`. During the rc.1
   window the macOS host moved `2.1.225` → `2.1.228` **mid-run** and the Windows
   host reached `2.1.229`, so the Windows column would have refused every
   Claude-sourced row before it began.

One rc.1 run also exported `CLAUDE_CONFIG_DIR` and `CODEX_HOME` but not
`GROK_HOME`, so the Grok source fell back to its documented default and indexed
the operator's real `~/.grok` sessions. The product was correct and the harness
was wrong; the contract still treats operator-tree access as a blocker, so that
run was discarded and restarted. The isolation rules below are not optional.

Two mandatory device runs start independently and may run in parallel:

1. Apple Silicon macOS (`darwin/arm64`); and
2. native Windows x64 (`windows/amd64`, never WSL).

Each device must report all 44 required A–D, F, and G rows, plus an explicit
`PASS`/`FAIL` for each of the six RC1 regression items R1–R6. The eight E rows
are optional per installed vendor. Gemini CLI, OpenCode, and Grok Build must not
be installed solely for acceptance; their absent rows are `NOT TESTED`. A
missing required result is `FAIL`.

  any provenance or identity failure. Source builds are supplemental only.

## Fixed isolation and controlled-session rules

1. Export **all five** vendor overrides before the first command, including for
   agents the run does not expect to touch. Each source falls back to its
   documented default when its variable is unset, so one omission silently
   reads the operator's real tree.

   | Vendor | Variable |
   | ------ | -------- |
   | Reinstate | `REINSTATE_HOME` |
   | Claude Code | `CLAUDE_CONFIG_DIR` |
   | Codex CLI | `CODEX_HOME` |
   | Gemini CLI | `GEMINI_CLI_HOME` |
   | Grok Build | `GROK_HOME` |

2. **OpenCode has no equivalent override.** It is read through
   `opencode session list`, which always targets the real store. Either skip
   OpenCode for the run and record its rows `NOT TESTED: no isolation override`,
   or record explicitly that OpenCode rows were collected **without** isolation.
   Never report an OpenCode row as isolated.
3. After the first index refresh, verify the session list contains **only**
   sessions the run itself created. Any unexpected session is an isolation
   failure: destroy the Reinstate home and restart, do not continue. Record the
   session count and the check result.
4. Use new absolute paths for `REINSTATE_HOME`, the install, private evidence,
   disposable Git repositories, temp files, and every vendor process home.
   Never point a command at the operator's real Claude, Codex, Gemini, OpenCode,
   or Grok tree.
5. Create the required Claude Code and Codex sessions through each vendor's own
   documented CLI in a disposable repository. A human may authenticate the
   throwaway home before the run; credentials and auth contents stay invisible
   to the acceptance agent and report.
6. Fully close the source CLI before every flagship handoff. Handoff execution
   may launch the destination CLI, but Reinstate itself must not create or edit
   a vendor session-store file. Unit tests use fake runners and no network or
   real vendor process.
7. Keep all raw output, timings, hashes, capsule bodies, and terminal recordings
   under the private evidence root. Commit only counts, hashes, timings, exit
   codes, mode labels, and paraphrased destination acknowledgements.
8. Never run `rein init`, configure a backend, sync a capsule, inspect a
   keychain or `.env`, or transfer a real transcript between devices. Use only
   fresh controlled sessions and the tagged synthetic fixtures. Do not reuse any
   rc.1 corpus, home, capsule, lineage store, or report row.

Before and after each relevant row, fingerprint the controlled source artifact
and vendor trees. A changed source hash, unexpected vendor write during a
launch-free row, access to an operator tree, or committed sensitive content is
a release blocker.

## RC1 regression re-verification (required, both devices)

Record an explicit `PASS`/`FAIL` and sanitized evidence for each. Any `FAIL`
here is release-blocking even when the corresponding A–G rows pass, because
these are the defects that failed rc.1.

### R1 — Claude source probes without a `version` file

Confirm the throwaway `CLAUDE_CONFIG_DIR` contains no file named `version` and
do not create one; a real installation has none. Then, on a real installed
Claude Code:

- `rein handoff claude:<id> --to codex --dry-run --json` must not exit `5` for
  any version reason, and must not report the source agent `UNTESTED`.
- `rein inspect` on the same session, in the same shell, must report the **same**
  version the handoff gate used. Two different answers for one agent in one
  invocation is a `FAIL` regardless of exit codes.
- Walk the shared contract on both Claude and Codex sources and record one row
  each: an unrecognized layout is `UNSUPPORTED`; a determinable in-range version
  is `SUPPORTED`; a determinable out-of-range version is `UNTESTED` and exits
  `5` with no artifact or lineage residue (this is C8's condition, recorded
  again here); a version that cannot be determined at all is `SUPPORTED` on
  layout alone. Produce the last case honestly — move the source executable off
  the curated `PATH` inside the throwaway environment — because a handoff must
  work when the source agent is gone.

### R2 — reader-emitted paths are tokenized

Create controlled Claude and Codex sources that actually read a file, so the
transcript carries tool-call inputs, tool results, and an attachment reference
with real absolute paths. Include one path outside every configured root.

- The handoff must complete. A failure with
  `capsule: absolute filesystem path is not allowed` is a `FAIL`.
- Privately scan the capsule, `projection.md`, the bootstrap, and every exported
  artifact for source-device absolute paths and for the operator's home
  directory name. Record zero/nonzero counts only; nonzero is a `FAIL`.
- Require `${REPO:<id>}` and `${HOME}` tokens for in-root paths and
  `${EXTERNAL:<digest>}/<basename>` for the out-of-root path. The external form
  must be a digest and a basename, never a reconstructable location.
- Prose is untouched: a sentence that merely names a path is carried as written.

### R3 — `changed_files` reflects the live working tree

Use a disposable repository with a deliberately dirty tree: at least one staged,
one unstaged, and one untracked file.

- The capsule must contain a non-empty `changed_files` key, `projection.md` must
  list those files, and the destination bootstrap must carry them.
  `Changed files: (none)` over a dirty tree is a release blocker.
- Every entry must be a `${REPO:<id>}/…` token. No absolute path may appear.
- Force both drop points — more than 64 changed paths for the probe cap, and a
  path set large enough to pressure the 8 KiB argv bootstrap budget — and
  require an explicit rendered count of omitted entries in each case. A silently
  short list is a `FAIL`.
- Confirm path lists stay out of the probe report's JSON: `verify`/`doctor`
  output is printed and pasted, and only the capsule holds paths.
- Confirm a transcript file claim is marked `evidence_conflicts_with_workspace`
  only when live Git produced a complete observation. An unavailable, uncertain,
  or capped observation must be reported as missing evidence, not as
  counter-evidence.

### R4 — a timed-out version probe is not an absent agent

- With an out-of-range source or destination agent, run the handoff gate while
  the host is deliberately loaded enough to make a two-second probe miss its
  budget (for example, with the full test suite running in parallel). Require
  exit `5`, not `0`. An accepted out-of-range agent under load is a `FAIL`.
- Confirm the retry policy: a timed-out probe is measured once more with a
  larger budget; a non-zero exit is not retried.
- Confirm an agent that is genuinely absent still resolves `SUPPORTED`, so the
  fix did not trade a rare fail-open for a rare fail-closed.
- Record this as production-reachable behavior, not a harness artifact.

### R5 — a message beginning with a slash is prose

Create a controlled source session whose first user message begins with `/init`,
whose history includes `/compact`, and whose prose names an absolute path.

- The handoff must complete. An abort with
  `capsule: absolute filesystem path is not allowed` is a `FAIL`.
- The message text must reach the projection exactly as written.
- Confirm the invariant still bites: a genuine path-typed violation (an absolute
  path planted in a path-typed field via the tagged fixtures) must still be
  refused, and the refusal must name the offending field.

### R6 — Claude ceiling through `2.1.229`

- Record the installed Claude Code version before the run and confirm `rein`
  calls it `SUPPORTED`. `2.1.228` and `2.1.229` must both be in range.
- Confirm `2.1.230` still fails closed as `UNTESTED`, so the range stayed
  inclusive without becoming open-ended.
- `2.1.229` has no physical evidence before this run; this run is what supplies
  it. If the host auto-updates past `2.1.229` mid-run, stop and report under the
  version-recording rule above.

## Execution map for the Phase 4 matrices

Read the acceptance contract's pass condition for every ID; the instructions
below define how to collect it. Do not collapse IDs into one result.

### A — flagship quota-switch

- Create one benign task in each required source with a current goal, latest
  request, changed file, known test result, and next action. Include a harmless
  completed marker write so A6 can prove it is not repeated. Leave the working
  tree dirty so A5 and R3 exercise a real changed-file list.
- For A1 and A2, close the source process, remove its auth variables from the
  test shell, run the installed `rein handoff` into the other agent from a real
  TTY, and confirm no source process or source API dependency appears. For A3,
  repeat Claude → Codex from a logged-out throwaway source environment.
- For A4, use a fresh controlled session whose vendor CLI is terminated during
  its final response so the vendor naturally leaves an incomplete final record;
  do not hand-edit its store. Confirm the last complete user intent survives.
- For A5–A6, allow only the destination's requested acknowledgement. Paraphrase
  its restatement in the report and prove the harmless source marker did not
  change. A5 now includes the changed-file list: a destination that restates the
  repository as clean while the tree is dirty fails A5 and R3. Do not authorize
  additional destination actions.
- For A7, record sanitized `handoff list`/`inspect` evidence: Claude's pinned
  destination ID resolves; Codex is truthfully `resolved`, `unresolved`, or
  `ambiguous`.

### B — fidelity and policy

- Run the tagged `TestHandoffExecutedOutputMatchesDryRunByteForByte` test, then
  compare installed-artifact `--dry-run` and `--no-launch` structured-plan
  stdout and stderr as separate byte sequences for the same frozen source and
  flags. The real-launch route is independently required by A1–A2. Any mismatch
  fails B1; never normalize paths, whitespace, or line endings for comparison.
- Use the tagged 200-turn fixture for B2 and G1. Run checkpoint, balanced, and
  full policies on frozen controlled sources. Record projection size, token
  estimate, truncation count, and sidecar-reference count without recording
  content.
- Inspect sanitized fidelity metadata for all five classes, attachment metadata,
  and unknown opaque records. Each class and every omission/reference needs its
  reason; never paste the capsule or projection into the report.

### C — workspace and capability truth

  frozen Git identities. Compare reported branch, HEAD, and dirty state to Git;
  create a controlled transcript/Git contradiction and require live Git to win.

  canonical project mapping. Require `${REPO:<id>}` portability and scan private
  artifacts to prove no source-device absolute path survived. C5 and R2 are
  collected from the same artifacts but recorded as separate results.

  and instruction declarations. Require missing-capability reports before
  launch and verify reports contain no values or file contents.
- Exercise one out-of-range source or destination version in a throwaway home.
  Require exit `5` and no artifact or lineage residue.

### D — security

- Run all tagged `internal/handoff` adversarial tests and `make fixture-scan`.
  Exercise the installed CLI against the tagged injection, delimiter,
  source-instruction, secret, oversized, `absolute-paths`, and `slash-commands`
  fixtures through disposable roots.
- Privately search every produced artifact for planted synthetic secrets,
  source authority text, and unescaped delimiters. Record only zero/nonzero
  counts. `--show-redactions` may expose categories and counts only.
- Prove launch-free rows do not read credentials and do not change any vendor
  tree. For real destination launches, attribute new vendor files to the vendor
  process and require the source tree to remain byte-identical.
- Verify owner-only storage, capsule sync exclusion, source SHA-256 immutability,
  the Grok warning, forced Grok redaction, and `--no-redact` refusal with exit
  `2`. Grok evidence uses a tagged synthetic fixture when Grok is absent.
- D7 covers every vendor tree the five isolation variables point at, plus
  OpenCode storage. If OpenCode was collected un-isolated, say so on D7 rather
  than claiming an isolated result.

### E — optional source-only agents

If a vendor is already installed, create a fresh controlled source in its
throwaway process home and run both allowed destinations. Test rewinds,
OpenCode storage/fallback truth, forced Grok redaction/warning, and destination
refusals. If absent, record the applicable rows `NOT TESTED: vendor absent`.
Grok native continuation is refused for the documented read-only reason. Gemini
CLI, OpenCode, and Grok Build remain **source-only**; Claude Code and Codex are
the only destinations.

### F — CLI contract

- Exercise human and JSON output for `handoff`, `list`, `inspect`, `export`,
  `resume --with`, and picker `h NUMBER`. Require the mode label `structured
  handoff` and new-destination-session truth everywhere. Any surface that says
  "resume", "same session", "lossless", or "full context" for a cross-agent
  operation fails F1.
- Check `--json` gating; exact, missing, duplicate, wildcard, and stale warning
  acknowledgement; launch-free exact-command output; stored artifact byte
  reproduction; ambiguous native references; and non-TTY fail-closed behavior.
- Record only exit codes `0`, `1`, `2`, `3`, `5`, `6`, or `7`. Any other public
  code is a release blocker.

### G — fixed performance plan

Use a monotonic process-start-to-exit clock, bounded capture, a 30-second
per-sample timeout, one untimed warmup where specified, and nearest-rank p95.
Validate every exit and result. Keep raw samples private.

| ID | Exact corpus and command | Samples | macOS ceiling | Windows ceiling |
| -- | ------------------------ | ------- | ------------- | --------------- |
| G1 | `go test ./internal/handoff -run '^TestLongHistoryParseCapsuleProjectionUnderCeiling$' -count=1 -v`; tagged 200-turn/400-event fixture | 1 | `<2,000 ms`, projection `≤98,304 bytes` | same |
| G2 | Installed `rein handoff SOURCE --to DEST --policy balanced --dry-run --json` on the largest frozen controlled local session | 1 warmup + 5 timed | maximum `8s` | maximum `12s` |
| G3 | Installed `rein handoff list --limit 100 --json` with exactly 100 valid stored lineage rows | 1 warmup + 20 timed | p95 `2s` | p95 `4s` |

Prepare G3 in a dedicated fresh home by running the same safe, frozen controlled
source through installed `--no-launch --json` exactly 100 times. This creates
100 valid append-only lineage records without spawning a vendor or hand-editing
the store. Require `list --limit 100 --json` to return exactly 100 rows before
timing. Fingerprint the source before and after setup.

G1's 2-second and 98,304-byte limits are the shipped deterministic unit
contract and are unchanged for this candidate, even though the projection now
carries a changed-file list it previously omitted. G2 uses the established cold
local-command envelope; G3 uses the established warm process-start envelope. The
looser Windows limits preserve the existing physical-host allowance without
permitting a 20–30 second regression. Because the rc.1 device runs produced no
certified timings, there is no prior physical baseline to compare against; treat
the ceilings as absolute and record a same-host comparison only against another
row from this run. A timeout, invalid output, source mutation, unbounded growth,
or more than 25 percent comparable same-host p95 regression is blocking even
inside an absolute ceiling.
