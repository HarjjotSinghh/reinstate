# v0.5.0-rc.2 tagged-artifact acceptance prompts

Use these prompts only after the signed `v0.5.0-rc.2` GitHub prerelease is
published and both live installer routes pin that exact tag. They specialize
the release-neutral
[Phase 5 acceptance contract](phase-5-universal-agent-coverage-acceptance.md)
and use the
[Phase 5 report template](results/phase-5-report-template.md).

`v0.5.0-rc.2` is the second universal-agent-coverage candidate, after
`v0.5.0-rc.1` dual-platform tagged-artifact acceptance FAILED (macOS 88/150,
Windows 93/150). It carries the pairing fix for Codex capsule `tool_result`
events, plus the
`internal/agents` catalog, `rein doctor --agents` (`AGENT-PROBE-V1` /
`--acceptance-matrix`), T1 discover for Kimi, Qwen, Pi, Cursor CLI, Copilot,
and Cline, and T2 handoff sources Gemini, OpenCode, and Grok. Claude Code and
Codex CLI remain the only T3/T4/T5 surfaces. Publication means ready for
physical acceptance; it does not mean acceptance passed. Current stable
remains `v0.4.0`. This candidate does not authorize stable `v0.5.0`.

Two mandatory device runs start independently and may run in parallel:

1. Apple Silicon macOS (`darwin/arm64`); and
2. native Windows x64 (`windows/amd64`, never WSL).

Each device must report all **150** required rows generated by
`rein doctor --agents --acceptance-matrix` on the tagged binary. Record that
count in the report header. A report whose count disagrees with the candidate
catalog is invalid. `PARTIAL` and `NOT TESTED` do not pass a required row.

## Fixed release identity and evidence boundary

- `TEST_TAG` is exactly `v0.5.0-rc.2`; `TEST_COMMIT` is its peeled literal
  40-character commit and must be an ancestor of `origin/main`.
- Require an annotated tag with a valid signature against
  `.github/allowed_signers` and a published non-draft prerelease tied to it.
- Install from the live bootstrap into a new directory after proving the
  bootstrap pins exactly `v0.5.0-rc.2`. Never replace a user binary.
- Require `rein` and `reinstate` to have identical bytes and to report that
  tag and full commit.
- Rebuild the local session index. Do not replay a stale `v0.4.0` database
  without exercising G7.
- No real transcripts, prompts, credentials, or private paths in the report.

Do not promote Gemini to T3 on this candidate. Do not invent a reader for a
T0 agent. If a T1 agent is not installed, that is a scope reduction: drop
that agent to the highest tier both platforms verified, in the candidate,
before any later stable. Tiers are never claimed on one platform's evidence.

## What to run

1. **Matrix A** catalog integrity (A1–A10).
2. **Matrix B** probe and redaction (B1–B9).
3. **Matrix C** for every installed T1+ key (C1–C6). C1 requires real
   sessions in at least two distinct projects.
4. **Matrix D** for every installed T2+ key (D1–D5). Destinations remain
   Claude Code and Codex only.
5. **Matrix E** for Claude Code and Codex only (E1–E6). Physical journeys.
6. **Matrix F** for every T0 key (F1–F2).
7. **Matrix G** no regression vs `v0.4.0` (G1–G8).
8. **Matrix H** CLI contract and performance (H1–H6).

A structured handoff starts a **new** destination session. It is not a
cross-agent resume. Report it that way.

## Required installs

On both platforms, for Matrix G: Claude Code, Codex CLI, Gemini CLI,
OpenCode, and Grok Build.

For Matrix C on this candidate, also install and actually use: Kimi, Qwen,
Pi, Cursor CLI, Copilot, and Cline. One session is not enough.

Do **not** install Antigravity CLI on a host that still needs a clean Gemini
tree. The Antigravity installer copies Gemini setup into
`~/.gemini/antigravity-cli/`.

## Reports

- `docs/testing/results/<DATE>-macos-phase5-V050RC1.md`
- `docs/testing/results/<DATE>-windows-phase5-V050RC1.md`

Each report is committed on its own branch and is immutable after the
terminated device block. Only the macOS coordinator report may add
reconciliation, after independently verifying both commits.

Stable `v0.5.0` is authorized only when both reports are `PASS` with zero
release-blocking findings.
