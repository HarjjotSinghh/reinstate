# v0.3.0-rc.4 dual-platform agent prompts

Use these prompts so **Windows develops and proves** remaining product gates
**before** macOS cuts the release candidate. This replaces the old pattern of
macOS-only development followed by a late Windows acceptance FAIL.

## Can you hand these off right now?

**Yes.** You do **not** need a new branch created first.

| Prerequisite | Status / action |
| ------------ | --------------- |
| Shared product branch | **Already exists:** `fix/v0.3.0-rc4-windows-blockers` (PR [#115](https://github.com/HarjjotSinghh/reinstate/pull/115)) |
| Commit this prompt file | Operator or macOS agent pushes it onto that branch (see below) |
| Windows agent creates branch alone? | **Yes** — it can `git fetch` and check out `origin/fix/v0.3.0-rc4-windows-blockers` without help |
| Tag / pin `v0.3.0-rc.4` first? | **No** — do **not** tag until both pre-tag smokes pass |
| Merge #115 to main first? | **Optional.** Prefer finishing product work on the PR branch, then merge once Windows smoke + CI are green |

### Operator checklist before pasting prompts

**On either machine (once):**

```bash
git fetch origin
git checkout fix/v0.3.0-rc4-windows-blockers
git pull origin fix/v0.3.0-rc4-windows-blockers
# Ensure this file is on the branch (if not yet committed, commit + push it).
```

**Windows host prerequisites** (so the Windows Grok agent can run immediately):

- Native Windows x64 (not WSL for product work)
- 64-bit PowerShell 5.1 or 7+
- Git with access to `github.com/HarjjotSinghh/reinstate` (HTTPS or SSH)
- Go toolchain able to use `GOTOOLCHAIN=go1.25.12`
- For full smoke: MSYS2 or Git userland with `make`/`sh`, `gcc` (race), GoReleaser, Syft
- Claude Code **2.1.219–2.1.220** and Codex in-range if you want real session rows later
- Working directory: a **clean clone or worktree** of reinstate (not a dirty random tree)
- Optional: `gh` authenticated for PR comments

**macOS host prerequisites:**

- Same repo access; Apple Silicon fine
- Go 1.25.12 via `GOTOOLCHAIN`, `make`, goreleaser for local snapshot
- Do **not** start release pins until Windows posts pre-tag smoke PASS

### What the Windows agent can do alone

It can:

1. `git fetch origin && git checkout fix/v0.3.0-rc4-windows-blockers`
2. Fix the current Windows CI failure and remaining product gaps
3. Push commits to the same branch / update PR #115
4. Run native PowerShell pre-tag smoke

It should **not** invent a second product branch or cut `v0.3.0-rc.4`.

## Approach (do not change)

**One shared branch. Windows-first product. macOS integrator/release.**

- **Do not** use two independent feature branches and “merge later.”
- Shared branch: `fix/v0.3.0-rc4-windows-blockers` (PR #115), or rename later to
  `fix/v0.3.0-rc.4-dual-platform` only if both agents agree and retarget the PR.
- Windows owns product + native gates.
- macOS owns cross-platform verify + release cut **only after** Windows pre-tag smoke is green.
- Device acceptance (tagged-artifact matrix) happens **after** the RC is published.

## Start here (no waiting for macOS)
```powershell

If the dual-platform prompt file is missing, pull again or ask the operator — it should live at docs/testing/v0.3.0-rc.4-dual-platform-agent-prompts.md on this branch.

1. Work ONLY on fix/v0.3.0-rc4-windows-blockers (PR #115). Do not create a competing product branch.
2. Do NOT tag, publish releases, deploy website, or pin installers to v0.3.0-rc.4.
3. Do NOT force-push without explicit operator approval.

## Your ownership (you may edit)

- internal/executabletrust, internal/cli (human privacy output), related tests

- CITATION / website product.ts currentRelease for rc.4
- chore(release): prepare v0.3.0-rc.4
- Signing tags, GitHub release publish, Vercel deploy

## Success criteria — Windows pre-tag smoke (all required)
In native 64-bit PowerShell from repo root:

```powershell
$env:GOTOOLCHAIN = "go1.25.12"
Remove-Item Env:CGO_ENABLED -ErrorAction SilentlyContinue
git fetch --tags origin

# 1) Fix and prove the privacy test on Windows
go test ./internal/cli -count=1 -run TestLocalInspectHumanRedactsAbsoluteWorkspacePath
go test ./internal/cli ./internal/executabletrust ./internal/doctest -count=1

# 2) Broader tests
go test ./... -count=1
# make verify if make/sh available

# 3) Race with retained diagnostics
$env:CGO_ENABLED = "1"
go test ./... -race -count=1 -timeout=20m *>&1 | Tee-Object -FilePath $env:TEMP\rein-race.txt
Remove-Item Env:CGO_ENABLED -ErrorAction SilentlyContinue

# 4) Snapshot + PS gates (RC3 blocker #1)
# Need goreleaser (+ syft for SBOMs) on PATH
powershell -NoProfile -File .\scripts\snapshot.ps1
powershell -NoProfile -File .\scripts\stage-release-assets.ps1 -DistDir dist
powershell -NoProfile -File .\scripts\check-release-artifacts.ps1 -DistDir dist
powershell -NoProfile -File .\scripts\test-install.ps1 -DistDir dist

# 5) Extensionless Codex trust must remain PASS with real codex.exe/cmd on PATH outside repo
# 6) Human inspect must not print absolute workspace paths
```

Optional: one real throwaway Claude + Codex session create. If vendor auth blocks it, record sanitized FAIL — do not invent sessions. Human TTY remains human QA.

## Deliverables
1. Commits pushed to fix/v0.3.0-rc4-windows-blockers; PR #115 updated.
2. PR comment with WINDOWS-PRE-TAG-SMOKE table (each gate PASS/FAIL + exit code).
3. Handoff note for macOS: product-ready or blocked only by non-product items (vendor auth / human TTY).

Stop when Windows pre-tag smoke is green (or only non-product blockers remain). Do not cut RC4.
```

- Fix macOS-only breakages from shared Go changes

1. Shared branch stays coherent with Windows work
2. When ready: product merged + v0.3.0-rc.4 published as prerelease
3. Final handoff: TEST_TAG, TEST_COMMIT, release URL, paths to rc.4 device prompts
