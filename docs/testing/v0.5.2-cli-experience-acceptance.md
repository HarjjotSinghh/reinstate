# `v0.5.2` CLI experience acceptance

This is the release-neutral acceptance contract for the interactive surfaces
added in `v0.5.2`. It extends, and does not replace, the Phase 1 through Phase 5
matrices.

The authoritative behaviour is defined in
[CLI reference](../cli-reference.md) and
[the plan](../planning/v0.5.2-cli-experience/README.md).

## Evidence policy

The Phase 3 evidence policy applies unchanged. Two additions specific to this
work:

- **Never point an interactive surface at the developer's real agent tree.**
  Use `scripts/tuisandbox`, which builds a synthetic agent home. A screenshot or
  capture containing a real session title is a policy failure, not a passing row.
- **Do not export environment the real user would not have.** In particular, do
  not set `TERM` when testing on Windows. Setting it there hides the exact
  defect that made the interactive UI never appear on that platform.

## Required environments

Apple Silicon macOS (`darwin/arm64`) and native Windows x64
(`windows/amd64`, never WSL for the Windows column), as for every prior phase.

## Capture technique

Frame layout is proven by the committed golden frames, which are byte-identical
across platforms and are the authoritative layout evidence. Physical capture
proves only that the program runs and that the right degradation engaged.

Two traps, both of which produce a passing-looking capture of a broken frame or
a broken-looking capture of a correct one:

- Bubble Tea queries the terminal for background colour (`ESC ] 11 ; ?`) and
  cursor position (`ESC [ 6n`) at startup and waits for a reply. A driver that
  only reads captures the queries and nothing else. Answer them.
- conhost rewrites runs of spaces as `ESC [ N C` cursor-forward moves. Stripping
  CSI sequences with a regular expression therefore collapses every column and
  makes correct output look broken. Replay through a real terminal emulator.

Bubble Tea clears the screen on exit, so snapshot the stream before sending the
quit key, or terminate the process rather than quitting it.

## The demo bench: `scripts/tuisandbox`

`scripts/tuisandbox` builds a throwaway agent home containing nine synthetic
sessions, one per readiness state, plus fake `claude` and `codex` binaries. It
never reads or writes the developer's real `~/.claude`, `~/.codex`, or
`~/.grok`: everything lives under `-root`.

```sh
make build
eval "$(go run ./scripts/tuisandbox -root /tmp/rein-tui)"
./bin/rein
```

The shell fragment goes to stdout; a legend naming every row and the commands to
exercise it goes to stderr, so `eval` keeps working.

**`-root` must be outside any Git checkout.** `internal/executabletrust` treats
the outermost `.git`-marked ancestor of the workspace as a trust boundary and
drops every `PATH` entry beneath it, so a root inside a repository would make
`<root>/bin/claude` unresolvable and block all nine rows on `agent.executable`.
The generator refuses such a root and exits 2 rather than producing a bench that
looks broken.

### The nine rows

| Row | Agent | Project | State | Mechanism |
| --- | ----- | ------- | ----- | --------- |
| R1 | claude | `auth-refactor` | READY | seeded baseline, clean repo, branch matches |
| R2 | codex | `keyring-store` | READY | same, on the Codex side |
| W1 | claude | `website` | WARN ×4 | no baseline + branch drift + untracked file + `.nvmrc` |
| W2 | codex | `search-index` | WARN ×3 | no baseline + recorded `commit_hash` mismatch + future `go` directive |
| W3 | claude | `deps-bump` | WARN ×1 | no baseline only — flips to READY after one acknowledged resume |
| W4 | claude | `checkout-flow` | WARN ×1 | seeded baseline + detached HEAD — permanently amber |
| B1 | grok | `payment-adapter` | BLOCKED | read-only record; preflight never runs |
| B2 | claude | `gone-missing` | BLOCKED | workspace never created, exit 5 |
| B3 | codex | `repo-drift` | BLOCKED | foreign `repository_url`, exit 7 |

R1 and R2 are READY on first launch because the generator seeds their prelaunch
baseline the same way `rein resume` does — otherwise `baseline.unavailable`
would make every healthy row amber.

### Exercising it

```sh
./bin/rein                                              # switcher, 9 rows, 3 glyphs
./bin/rein sessions --json | jq .
./bin/rein resume <R1> --dry-run --json | jq .environment.decision
./bin/rein resume <W1> --dry-run --json \
  | jq '[.environment.checks[]|select(.severity=="warning")|.id]'
./bin/rein inspect <B1> --json | jq .session.read_only_reason

# W3 heals itself: acknowledge once, and it is READY on the next visit.
./bin/rein resume <W3> --allow-environment-warning baseline.unavailable
./bin/rein resume <W3> --dry-run --json | jq .environment.decision

# Handoff. Run it from the workspace: rein refuses a cwd in a different
# repository, and baseline.unavailable is always a warning on a handoff.
cd "$HOME/Projects/auth-refactor"
rein handoff <R1> --to codex \
  --allow-warning baseline.unavailable \
  --allow-warning handoff.capability.attachment.support
rein handoff list --json | jq '.[-1].destination'   # -> state "resolved"
```

Two generator flags:

- `-scripted` also exports `REINSTATE_ALLOW_NON_TTY_LAUNCH=1`, which any
  non-interactive smoke test needs. It is off by default so a hand-driven demo
  hits the same TTY requirement production does.
- `-stale-claude` puts an out-of-range Claude shim (`2.1.300`) first on `PATH`.
  Every Claude row then blocks on `agent.version` with exit 5. Version state is
  necessarily global — the executable name is fixed per agent by the catalog —
  so it is a generator flag, not a per-row lever.

To demo the other handoff outcome, copy `<root>/bin-stale/codex-silent` over
`<root>/bin/codex`. It launches and exits 0 without writing a rollout, so
lineage records `launched=true` with `destination.state="unresolved"`.

### Known limits of the bench

- **A handoff can never reach `ready`.** `BindWorkspace` passes no baseline, so
  `baseline.unavailable` is structurally always present, and the pipeline
  requires every warning acknowledged. READY has to be demonstrated with
  `rein resume`.
- **The switcher shows no read-only reason for B1.** The `read-only: <reason>`
  preview line is guarded on the prober being nil, and it never is for
  interactive `rein`. B1 reads CANNOT RESUME with nothing on screen explaining
  why; `rein inspect` shows it. This is a TUI fix, not a bench fix.
- **The Windows shims are unverified.** They are written and shaped for
  `PATHEXT`, but no run on a Windows host has exercised them, and the Windows
  handoff substitutes a single-line bootstrap that the batch shim does not
  reproduce.

### Two defects this verification caught

Both were invisible to every unit test and to macOS, and both would have shipped.

1. **`TERM` unset disabled the whole interactive UI on Windows.** The ladder
   treated an unset `TERM` as `dumb`. On Unix that is right; on Windows `TERM`
   is simply absent, so the switcher, studio, wizard, and palette would never
   have appeared there. Found by running the real binary with a clean
   environment; earlier runs had exported `TERM` in the command and hid it.
   `internal/ui` now carries a per-platform `unsetTermIsDumb`.

2. **A full-screen program was started against in-memory streams and blocked.**
   After the fix above, the Windows `internal/cli` suite hung for 600 seconds.
   The ladder honoured an injected terminal check while stdin was a
   `strings.Reader` — but raw mode needs a file descriptor. "Is this a TTY" and
   "can this host a full-screen program" are now separate questions:
   `internal/cli` requires real console handles before choosing an interactive
   surface, and the non-TTY refusal still uses the injected check alone.

### Unrelated pre-existing failures

- `TestHandoffFromRealisticClaudeInstall` fails only when test packages run
  concurrently, and passes under `go test -p 1`. The test installs a fake
  `codex` on `PATH` and reads its version through a bounded probe; under load
  that probe times out and the destination reads as untested.
- `TestLocalMarkdownLinksResolve` fails on links inside the untracked
  `videos/` tree.
