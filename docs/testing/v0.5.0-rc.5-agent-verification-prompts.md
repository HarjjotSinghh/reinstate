# v0.5.0-rc.5 tagged-artifact acceptance prompts

Use these prompts only after the signed `v0.5.0-rc.5` GitHub prerelease is
published and both live installer routes pin that exact tag. They specialize
the release-neutral
[Phase 5 acceptance contract](phase-5-universal-agent-coverage-acceptance.md)
and use the
[Phase 5 report template](results/phase-5-report-template.md).

`v0.5.0-rc.5` is the fifth universal-agent-coverage candidate. Physical
`v0.5.0-rc.4` acceptance found one defect that made every other reader fix
unreachable: **an index never re-read a source after Reinstate itself
changed**. Both layers of change detection asked only whether a file had
moved — `ReplaceSource` compared source path, modification time and size, and
an unchanged source fingerprint skipped the scan outright — so an upgrade left
an existing index frozen and a reader fix reached nobody until the user's agent
happened to write a new session. On the Windows host an index built before the
Gemini workspace fix kept serving 24 sessions with no workspace indefinitely.
That is now bound to the reader identity, and the same index heals on the first
run of the new build.

This candidate also carries: Gemini project paths recovered on a
case-insensitive filesystem, where the CLI records a lower-cased path but
hashes the real on-disk case, so no Windows Gemini record resolved a workspace;
an agent root environment override made authoritative even when it names a path
that does not exist, which previously fell back to walking the operator's real
home tree while still reporting `root_env_set`; Cursor CLI's verified root
variable, so it is no longer the one indexed agent that cannot be redirected;
an incremental refresh that skips parsing an unchanged source; and Windows
portability of the documentation tests on a checkout that does not live on the
system drive.

It raises the verified vendor ranges to Claude Code `2.1.238` and Codex CLI
`0.149.0`. Both ceilings moved on dual-platform physical evidence, not a
version bump: on each platform a session was created with the new version,
indexed by Reinstate, and resumed through the launch plan Reinstate itself
produced, and the resumed session returned a token that existed only in the
original session's history.

Publication means ready for physical acceptance; it does not mean acceptance
passed. Current stable remains `v0.4.0`. This candidate does not authorize
stable `v0.5.0`.

Two mandatory device runs start independently and may run in parallel:

1. Apple Silicon macOS (`darwin/arm64`); and
2. native Windows x64 (`windows/amd64`, never WSL).

Each device must report all **150** required rows generated by
`rein doctor --agents --acceptance-matrix` on the tagged binary. Record that
count in the report header. A report whose count disagrees with the candidate
catalog is invalid. `PARTIAL` and `NOT TESTED` do not pass a required row.

## Fixed release identity and evidence boundary

- `TEST_TAG` is exactly `v0.5.0-rc.5`; `TEST_COMMIT` is its peeled literal
  40-character commit and must be an ancestor of `origin/main`.
- Require an annotated tag with a valid signature against
  `.github/allowed_signers` and a published non-draft prerelease tied to it.
- Install from the live bootstrap into a new directory after proving the
  bootstrap pins exactly `v0.5.0-rc.5`. Never replace a user binary.
- Require `rein` and `reinstate` to have identical bytes and to report that
  tag and full commit.
- Rebuild the local session index. Do not replay a stale `v0.4.0` database
  without exercising G7.
- No real transcripts, prompts, credentials, or private paths in the report.

## What this candidate specifically re-tests

The stale-index defect is not visible in a clean run: a fresh index has nothing
stale to serve. Exercise the upgrade path deliberately.

- Build an index with the **previous** release, then open it with the tagged
  binary and confirm rows the old reader could not resolve are re-read. On the
  Windows host this was Gemini workspaces: 0 resolved before, 10 after.
- Then confirm an unchanged refresh is still materially faster than a cold one
  (H4), because the reader identity must be stable *within* one build.
- Confirm an agent root variable pointed at a path that does not exist reports
  the agent absent, and does **not** fall back to the home tree (B7).

## Reading a refusal correctly

Several refusals in this product are correct behaviour and must not be scored
as defects. A row fails only when the refusal is wrong, not when it fires.

- `working directory is a different repository than the source session` — run
  from the session's own workspace.
- `the recorded Git branch cannot be verified outside a Git repository` — the
  chosen session's workspace is not a repository; choose one that is.
- `source session is active; close it or pass --allow-active` — the operator is
  running that agent. For an embedded store, any write to the database counts.
- `native agent version X is outside the verified range` — the host's vendor CLI
  auto-updated past the ceiling. Pin the verified version or record the drift.

Equally, a harness that redirects an agent with a variable the product does not
declare is testing the operator's real root, not a copy. Read each agent's
`root_env` from `rein doctor --agents --json` rather than assuming a name.

## Required installs

On both platforms, for Matrix G: Claude Code, Codex CLI, Gemini CLI,
OpenCode, and Grok Build.

For Matrix C on this candidate, also install and actually use: Kimi, Qwen,
Pi, Cursor CLI, Copilot, and Cline. One session is not enough.

Do **not** install Antigravity CLI on a host that still needs a clean Gemini
tree. The Antigravity installer copies Gemini setup into
`~/.gemini/antigravity-cli/`.
