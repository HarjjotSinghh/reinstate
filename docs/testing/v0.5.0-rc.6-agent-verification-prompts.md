# v0.5.0-rc.6 tagged-artifact acceptance prompts

Use these prompts only after the signed `v0.5.0-rc.6` GitHub prerelease is
published and both live installer routes pin that exact tag. They specialize
the release-neutral
[Phase 5 acceptance contract](phase-5-universal-agent-coverage-acceptance.md)
and use the
[Phase 5 report template](results/phase-5-report-template.md).

`v0.5.0-rc.6` is the sixth universal-agent-coverage candidate. Physical
`v0.5.0-rc.5` tagged-artifact acceptance ran the full matrix on both platforms
and failed **one** required row: **B4** on macOS. The agent probe carried a raw
38-character Git object hash into its artifact.

OpenCode keeps a Git object store under each snapshot, and Git stores an object
as a two-character directory plus a thirty-eight character file. The shape
normalizer recognised only exactly 32, 40 and 64 characters, so a 38-character
stem matched nothing and reached the artifact verbatim. Those names are content
hashes of the operator's own repository, which is precisely what a committed
probe must not carry. Any hex run long enough to identify content is now
collapsed to `<N-hex>`; the established `<32-hex>`, `<40-hex>` and `<64-hex>`
tokens are unchanged, so committed artifacts do not churn.

Everything else in `v0.5.0-rc.5` passed on both platforms, including the
upgrade path that the previous candidate existed to fix: an index built by the
previous release and then opened by the tagged binary re-read what the old
reader could not resolve — 0 to 3 resolved workspaces on macOS and 0 to 10 on
Windows — without losing a row, and the previous release could still reopen it.

Publication means ready for physical acceptance; it does not mean acceptance
passed. Current stable remains `v0.4.0`. This candidate does not authorize
stable `v0.5.0`.

Two mandatory device runs start independently and may run in parallel:

1. Apple Silicon macOS (`darwin/arm64`); and
2. native Windows x64 (`windows/amd64`, never WSL).

Each device must report all **150** required rows generated by
`rein doctor --agents --acceptance-matrix` on the tagged binary. Record that
count in the report header. A report whose count disagrees with the candidate
catalog is invalid. `PARTIAL` and `NOT TESTED` do not pass a required row.

## Fixed release identity and evidence boundary

- `TEST_TAG` is exactly `v0.5.0-rc.6`; `TEST_COMMIT` is its peeled literal
  40-character commit and must be an ancestor of `origin/main`.
- Require an annotated tag with a valid signature against
  `.github/allowed_signers` and a published non-draft prerelease tied to it.
- Install from the live bootstrap into a new directory after proving the
  bootstrap pins exactly `v0.5.0-rc.6`. Never replace a user binary.
- Require `rein` and `reinstate` to have identical bytes and to report that
  tag and full commit.
- Rebuild the local session index. Do not replay a stale `v0.4.0` database
  without exercising G7.
- No real transcripts, prompts, credentials, or private paths in the report.

## What this candidate specifically re-tests

**B4 needs an agent root that contains a Git object store.** A clean host may
not have one, and the row then passes without exercising the fix. Use OpenCode
in a Git repository so a snapshot object store exists, then confirm no
`name_shapes` entry carries a hex run of twelve or more characters — at any
length, not only 32, 40 or 64.

**The upgrade path is invisible in a clean run.** Build an index with the
previous release, then open it with the tagged binary and confirm rows the old
reader could not resolve are re-read. Then confirm an unchanged refresh is
still materially faster than a cold one (H4), because the reader identity must
be stable within one build.

**An agent root variable pointed at a path that does not exist** must report
the agent absent and must not fall back to the home tree (B7).

## Reading a refusal correctly

Several refusals in this product are correct behaviour and must not be scored
as defects. A row fails only when the refusal is wrong, not when it fires.

- `working directory is a different repository than the source session` — run
  from the session's own workspace.
- `the recorded Git branch cannot be verified outside a Git repository` — the
  chosen session's workspace is not a repository; choose one that is.
- `source session is active; close it or pass --allow-active` — the operator is
  running that agent. For an embedded store, any write to the database counts.
- `native agent version X is outside the verified range` — the host's vendor CLI
  auto-updated past the ceiling. Pin the verified version or record the drift.

## Harness traps that produce a wrong verdict

Physical `v0.5.0-rc.5` acceptance found more harness defects than product
defects, and two of them were **false passes**. Check the harness before
concluding the product is wrong.

- Read each agent's `root_env` from `rein doctor --agents --json` rather than
  assuming a variable name. Redirecting with a variable the product does not
  declare tests the operator's real root, not the copy.
- Put the candidate on `PATH` under **both** `rein` and `reinstate`, or an
  installed release answers instead and the comparison runs between two builds.
- A `--dry-run` capsule is a preview and carries no `raw_source` boundary. Only
  a harness that truncates a copied source can measure D4.
- Faking a vendor version needs a shim the platform will actually execute: a
  `.cmd` file is inert on macOS, so the real binary answers and an in-range
  version reads as "the refusal did not fire".
- Assert that a refusal **names a range**, not that it names a particular
  version. Hardcoded bounds stop testing the message the moment a ceiling moves.
- Attribute a write before blaming it on a refresh. Any agent the operator is
  running writes to its own root continuously, and the audit may itself be
  running inside one.
- `os.path.basename` of a drive root is empty; `D:` is the correct project name
  for a workspace of `D:\`.
