## Fixed release identity and evidence boundary

- `TEST_TAG` is exactly `v0.6.0-rc.6`; `TEST_COMMIT` is its peeled literal
  40-character commit and must be an ancestor of `origin/main`. **`TEST_COMMIT`
  is filled in once the signed tag exists** — it is not yet known while this
  candidate is only a reviewed release commit on `release/v0.6.0-rc.6`.
- Require an annotated tag with a valid signature against
  `.github/allowed_signers` and a published non-draft prerelease tied to it.
- Install from the live bootstrap into a new directory after proving the
  bootstrap pins exactly `v0.6.0-rc.6`. Never replace a user binary.
- Require `rein` and `reinstate` to have identical bytes and to report that
  tag and full commit (`rein version --json`). Report both the tag and the
  full commit in the device report header.
- Rebuild the local session index. Do not replay a stale index without
  exercising the reader's own upgrade path.
- **Host environment.** Every shell that runs `rein`, the Hop lab, or a Go
  test must `unset REINSTATE_BACKEND REINSTATE_MEMORY_BACKEND_DIR` first;
  `rein` honours `REINSTATE_BACKEND` before it reads the profile, so a
  contaminated shell silently uses a local store and every Hop row reports
  nothing to the control plane. The report must state that every shell did
  this. Do **not** unset the host's `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, or
  `XDG_DATA_HOME`: they are its live agent homes, and a Claude Code run
  spawned without `CLAUDE_CONFIG_DIR` falls back to a stale `~/.claude` that
  cannot refresh its sign-in. Isolate a row by pointing the vendor's home
  variable at your own directory. This rule is unchanged from `v0.6.0-rc.5`.
- **Always invoke the tagged binary by its full path**, never bare `rein`
  or `reinstate` — a PATH-resolved binary can silently answer from an
  older installed release. Put the tagged binary's directory first on
  `PATH` only as a convenience for the maintainer's own console commands
  below, and confirm `rein version --json` reports the exact tag before
  relying on it.
- **ConPTY console rule.** Every row that needs a live, running vendor
  process (`E1`–`E3`-shaped rows, `grok:E1`–`E3` included) launches that
  process in a real Windows pseudo console via
  [`scripts/testing/conptydriver`](../../scripts/testing/conptydriver) or
  the maintainer's own interactive terminal — never headless, and never a
  bare, unattached process the harness cannot observe completing.
- No real transcripts, prompts, credentials, or private paths in the report.
  The grok console transcript below is the one exception this dispatch asks
  for by design (see "Maintainer console evidence" below): record it in
  full, verbatim, and redact nothing from it, but do not embellish or
  summarize over it either.

7. Confirm the catalog reflects both sessions:

## Lab isolation for `MatrixH:H7`

Refined 2026-09-08 after three tagged-artifact exercises of the corrected
fresh-Hop-account rule on `v0.6.0-rc.5` (the run itself, plus two
same-artifact rechecks) all reached, or nearly reached, the daemon
mechanism, and none produced a clean `PASS` under aggregate byte-for-byte
digest equality — see
[`v0.6.0-windows-acceptance.md`](v0.6.0-windows-acceptance.md#run-notes)
and
[ADR 0005 Amendment 2](../adr/0005-v0.6.0-scope-and-windows-first-acceptance.md#amendment-2-2026-09-08)
for the full rationale.

- **"Fresh Hop lab account"** means a new **Hop** account created through
  the lab's `hopd` (`hoplab pair init`, or the `rein account init` flow
  against the lab control plane) that has had **zero sessions pushed to
  it** — not a new Windows OS user account. Unchanged from `v0.6.0-rc.5`.
- **(a) Full per-file listing, before and after.** Before the round trip,
  and again after it, list every file (relative path, size, mtime) under
  exactly the **session-bearing subtrees**, not the whole agent-home
  roots: `<CLAUDE_CONFIG_DIR>/projects`, `<CODEX_HOME>/sessions`, and
  `<XDG_DATA_HOME>/opencode`, excluding `*-wal`, `*-shm`, and `*.lock`
  files. Read `CODEX_HOME` as the **persistent, user-level** value the
  scheduled task will actually see (a `daemon status` call's reported
  `roots`, or the registry) — never the executing shell's own transient
  `CODEX_HOME`, which the `v0.6.0-rc.5` second recheck showed can silently
  differ from it and invalidate the comparison.
- **(b) `PASS` condition.** The row is `PASS` only if all three hold: the
  daemon's pull restored **zero** snapshots; **no file** under those three
  subtrees was created or modified carrying a lab/synthetic name or a name
  matching the lab account's own session ids; and **every** differing
  entry between the before- and after-listings is attributable, by
  relative-path pattern, to a process other than `rein` (backup rotation,
  another session's own transcript or `file-history` writes, WAL/journal
  churn, and the like). Any entry that cannot be so attributed keeps the
  row at `PARTIAL` or worse — the burden is on the attribution, not on
  digest equality.
- **(c) Reporting.** The report lists every differing entry between the
  before- and after-listings by relative path, with its attribution, even
  when the overall disposition is `PASS` — a clean row still shows its
  work.
- **(d) `#424` itself.** The daemon reading the live roots and pushing
  into the run's disposable locker is **recorded, not failed**, on its
  own: `#424` is a documented design gap, scheduled to be fixed separately
  for `v0.6.1`, not a fresh finding each time `H7` runs until it lands.
- `H7` still needs the maintainer at the keyboard for the one UAC prompt
  the elevation raises — this refinement does not remove that requirement
  and must not attempt to route around it (see "Harness traps" below).
  Start the wait only **after every other row in the executor's part is
  already done**, not in parallel with them: poll
  `D:/ReinstateAcceptanceProjects/h7-go.txt` every **60 seconds**, for **up
  to 150 minutes**, and do not attempt the elevation until that file exists
  and its content confirms the maintainer is present to accept the prompt.
  If the file never appears within that full wait window, record `PARTIAL`
  (operator/harness availability) with that reason — a shorter poll window
  is not a basis for `PARTIAL`.

This lab-isolation method is a harness clarification only; it does not
change `rein daemon install`'s own behavior (that is `#424`'s own fix,
scheduled for `v0.6.1`, not attempted by this candidate) and does not
change what `MatrixH:H7`'s row scores on beyond the refined pass condition
itself.

## Reading a refusal correctly

Several refusals in this product are correct behaviour and must not be scored
as defects. A row fails only when the refusal is wrong, not when it fires.

- `working directory is a different repository than the source session` — run
  from the session's own workspace.
- `the recorded Git branch cannot be verified outside a Git repository` — the
  chosen session's workspace is not a repository; choose one that is.
- `source session is active; close it or pass --allow-active` — the operator is
  running that agent. For an embedded store, any write to the database counts.
- `native agent version X is outside the verified range` — the host's vendor CLI
  auto-updated past the ceiling. Pin the verified version or record the drift
  as `NOT TESTED (version drift)` per
  [`v0.6.0-windows-acceptance.md`](v0.6.0-windows-acceptance.md#dispositions-that-do-not-block-the-device-verdict).
- `could not reach the Reinstate Hop control plane at <url>: <cause>` (H1c) —
  correct when the control plane genuinely does not resolve; the row passes on
  the message shape and the `control_plane_unreachable` `--json` kind, not on
  the control plane being reachable.

## Harness traps that produce a wrong verdict

Physical acceptance on this program has repeatedly found more harness defects
than product defects, and some have been **false passes**. Check the harness
before concluding the product is wrong.

- Read each agent's `root_env` from `rein doctor --agents --json` rather than
  assuming a variable name. Redirecting with a variable the product does not
  declare tests the operator's real root, not the copy.
- Put the candidate on `PATH` under **both** `rein` and `reinstate`, or an
  installed release answers instead and the comparison runs between two
  builds. Always invoke by full path where the contract requires it, above.
- A `--dry-run` capsule is a preview and carries no `raw_source` boundary.
  Only a harness that truncates a copied source can measure the fidelity rows
  that need it.
- Assert that a refusal **names a range**, not that it names a particular
  version. Hardcoded bounds stop testing the message the moment a ceiling
  moves.
- A Hop row that passes without exercising its mechanism is `FAIL`. Check the
  harness (the lab's env, the isolated home, `hopd.db`) before trusting a
  green result.
- Attribute a write before blaming it on a refresh. Any agent the operator is
  running writes to its own root continuously, and the audit may itself be
  running inside one.
- `grok:E1`–`E3` specifically: do not attempt to drive these rows from the
  harness (headless or ConPTY) — that has already been tried and confirmed
  not to complete a turn in the current environment. Do not accept a
  maintainer transcript that skips a step, does not show the exact recall
  question asked, or does not show the exact token returned — a transcript
  that merely asserts success without showing the command output is not
  evidence.
- `MatrixH:H7` specifically: "fresh Hop lab account" means a new **Hop**
  account with zero pushed sessions, not a new Windows OS user account —
  do not abandon the row over a missing Windows account elevation the rule
  does not actually require. Do not attempt an unattended elevation
  workaround (a scheduled task that self-elevates, a stored credential,
  etc.) to route around the missing operator — the row's mechanism is the
  real UAC prompt, and routing around it is a false pass. Score the row
  against the refined per-file listing with attribution, not aggregate
  digest equality — a report that still computes and requires whole-root
  digest equality is scoring against the retired `v0.6.0-rc.5` rule. Start
  the go-signal poll only after every other row in the part is done, not
  before, and not in parallel.
